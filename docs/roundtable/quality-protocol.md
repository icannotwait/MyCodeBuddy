## 运行规模

固定 12 个任务：事实核查、方案权衡、反例追踪各 4。三模式、单模型、R0 与 R2 各 2 次，共 72 次运行。每个任务预先定义同一份资料可以回答的机会集，三种模式使用同一机会集，不按实际产出缩小分母。两次重复是两行独立运行。

## 评分行

原始行是 `QualityScoreRow { task_id, mode, repetition, check_id, check_type, rater_id, score:0|1, failure_type?, adjudicated_score?, evidence_ref }`。

`check_type` 只有三种：`seeded_error`、`substantive_response`、`minority_risk`。

实验前指定两位盲评者和一位分歧裁决者。同一次运行去掉模式名称和模型标记后独立评分，再按事先规则裁决。不按现场偏好删题。

指标先给出每个任务、每种模式两次重复的分子和分母，再给出宏平均，以及原始总分子和总分母。裁决门默认使用宏平均，不能混用口径挑选更好看的数。

## 三个比率

关键错误发现率 = 正确指出的预埋关键错误数 / 预埋错误机会数。

实质回应率 = 对预埋关键质疑给出有依据的回应数 / 预埋回应机会数。

少数风险保留率 = 主持结果准确保留的重要少数风险数 / 预埋风险机会数。

失败、超时、无成员输出或主持失败都保留对应机会。未交付项记 0，不从分母移除。机械的 assigned/answered coverage 另列，不代替语义回应分。

## 无依据结论与空输出

无依据新增结论记录 `unsupported_count` 与 `all_asserted_conclusions`。输出为空时该比例为 N/A，同时该次运行失败，三个机会指标记 0。不能因为零输出而得到“幻觉更少”的奖励。另报告失败率，以及每次运行的无依据结论计数。

## 建议门

建议门是安全零失败；R2 的宏平均关键错误发现率不低于两个基线；实质回应不低于 80%；少数风险保留不低于 90%；在有输出的运行中，无依据结论的比例和每次运行计数都不劣于基线。

这些数值仍须在 G0 和实验前批准。80 与 90 是提案，不是已经生效的统计结论。任一关键任务退步必须显式裁决修复或暂不开启，不能用平均掩盖。72 次小样本只能描述这一组任务在已报告额外消耗下的结果，不宣称等预算优势、显著性，或讨论机制单独带来的因果收益。更强结论需要另批预算匹配实验。

## 观测

报告每次运行的 ACP attempts、底层已观察请求数、房间活跃时长、失败类别、confirmed token 和 unknown measurement。保留全部失败样本。

运维指标通过 A03 `get(metrics)` 读取。P13 负责启动、quarantine 和拒绝原因；P14 负责 active、overrun 和预留；P16a 负责 unknown 与 diagnostic；P17 负责 event 与订阅水位。指标本身不得泄漏 token 或正文。P23 要核对接口返回值与故障轨迹，而不是只把指标名称写进操作文档。
