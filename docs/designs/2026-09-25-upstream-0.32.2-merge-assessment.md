## 1. 结论

**可以合入，但应作为一次 ACP 运行时迁移处理，不能当作普通版本升级。** 推荐从当前 main 建立隔离分支 `codex/sync-codeg-0.32.2`，执行一次保留双方历史的 merge，按本文顺序收敛，再通过 PR 合入 main。

本次实测 **75 个冲突文件：73 个内容冲突、2 个修改/删除冲突；304 处文本冲突**。其中 `connection.rs` 有 80 处，涉及双方不同的会话运行方式；`conversation-detail-panel.tsx` 的一处冲突包含上游约 2,000 行，因为本地已把主体拆到另一个文件。两者均不能整文件选边。

最小可行方案是沿用本地结构和上游的新协议实现，在共享入口适配。无需另造兼容层、保留两套 ACP runtime，也不建议把 109 个提交逐个 cherry-pick。

**必须在实现阶段证明的三个难点：**

1. 官方 ACP 2.2 下，本地 suspend/continue/resume、自治回合、watchdog、取消归因仍成立。
2. 快照大小限制与上游“工具卡/生成图片不丢失”目标存在真实冲突，不能只并两个函数。
3. 上游通知、时间线和 tab reparent 修复必须落到本地现有事件入口与会话组件，不能产生重复订阅或双份会话所有权。

## 4. 高风险冲突的具体处理

### 4.1 ACP：迁移运行时，不只是替换 import

上游新 `AgentSession::read_update()` 返回 `Dispatch`，不再返回本地旧循环使用的 `SessionMessage::{SessionMessage, StopReason}`。新实现说明：router 关闭时的 Err 是连接丢失，不是可以一直 continue 的单条解码错误；回合结束来自 `session/prompt` response。

解决顺序：

1. 接受官方运行时及 upstream `agent_session.rs`；迁入 `agent_process.rs`，保留 fork 进程退出、子进程清理与日志保护。原 vendor 文件发生 rename，不能删除 vendor 时连本地改动一起丢掉。
2. Cargo 保留 `tokio/time`、`kill_tree = =0.2.4` 与 `vendor/kill_tree` patch；删除 sacp 依赖、旧 schema 直接依赖与 sacp-tokio patch。采用上游 fork/notices/compaction features，保持 protocol V1，不开启 `unstable_protocol_v2`。
3. 统一迁移所有本地请求类型、Error、Responder、schema 到新运行时；编译验证 elicitation、boolean config、resume 等现有调用在新 schema 下的形状，不能凭旧 feature 名猜测新 API。
4. 以本地 `LaneSender`、注册后激活、route bootstrap、ConnectionPurpose、ResumeExistingOnly 与终端/路由请求构造为结构，接入上游新的 attach、Dispatch、prompt response 和 RequestCancellation。
5. 归并 `send_capturing_models` 与本地 load/resume/new 辅助逻辑，保留实际 session id、原始 models、terminal metadata、fork_point 以及失效 config 过滤。不要把本地多参数构造器直接替换成上游少参数版本。
6. 重写回合结束路径：prompt response 只结算一次；本地 suspension、watchdog、parent turn end、停止归因和持久化仍通过现有统一结算逻辑。agent request rejection 属于回合失败时应保持连接；router/进程丢失才进入连接结束。
7. 权限队列合并 withdrawal/RequestCancellation 与本地 plan-review 已发布集合、generation gate、drain 和 question reaper。撤销可见卡应提升下一张，撤销等待卡不应误取消当前卡。
8. Cursor 扩展、notices/compaction、Grok 用量、hosted terminal、OpenCode 元信息与节流日志接入同一事件路径；保留本地 host tools 权限边界与敏感信息处理。

**未报冲突但确认残留旧 API 的 4 个文件：**

```text
src-tauri/src/acp/grok_retry.rs
src-tauri/src/acp/terminal_adapter.rs
src-tauri/src/acp/terminal_context.rs
src-tauri/src/acp/xai_session_notification.rs
```

这四处在模拟合并 tree 中仍有 `sacp::` 引用，因此不是抽象风险。应与 connection 一起迁移，再全树搜索旧 API；单纯收完 75 文件一定遗漏这部分工作。

`registry.rs` 保留 `codex_distribution()` 和 `CODEX_ACP_USE_CLI=0`，在 helper 内升至 1.13.1，同时改同文件其它 pin 断言及 preflight。上游冲突测试夹带 `AgentType::OpenClaw`，仅接收仍支持的 agent 更新，不恢复这个变体。

### 4.2 快照：两种裁剪契约冲突，必须显式取舍

本地 `SnapshotLimits::default()` 为 payload 3 MiB、128 tool calls、64 images、256 failures、512 watchdog tombstones；单图超过 64 KiB 会用 `codeg:omitted-oversized-image` 替代。上游新方案保留全部工具身份/meta 和图片，只优先裁掉旧的已结束工具输出，2 MiB 是可裁剪 payload 预算，**不是总大小硬上限**。

因此“原样保留全部图片/工具”与“保留本地有界投影”不能同时声称完成。推荐本轮以本地有界投影为硬约束，移植上游的按到达顺序优先保留新输出、保护活跃工具和委托关联信息的思路，同时修正前端对省略数据的表现：

- 不把 `codeg:omitted-oversized-image` 当作生成失败；展示已成功但预览被省略的状态，已有合法 URI 可用时沿用既有读取路径。
- 被快照省略的工具引用不得静默变成“从未出现”，使用已有 truncation 信息恢复历史或明确显示省略状态；活动工具/权限不能被普通历史输出挤走。
- 保留 watchdog 版本/tombstone 与继续委托状态；元信息裁剪不能破坏 parent-child 绑定。
- 不新增无限 base64 传输，也不在本轮凭空搭建附件存储服务。

**验收限制：**这会保留 fork 的有界快照政策，不等价于上游“所有图片字节永远完整”的契约。若产品要求后者，需要另行设计按需读取或分页，不应作为普通选边隐藏在本次 merge 中。前述省略 UI/历史恢复仍需实现并验证，本报告不声称现有代码已经支持。

### 4.3 生命周期、`/clear` 和 transcript 身份

- `background_watch.rs` import 并集：保留 automation marker 判断，增加 `find_clear_rollover_successor`。
- `lifecycle.rs` 保留本地 critical lane、broker worker/overflow 与 Cursor enrichment，给相应生命周期过滤器接入 `TranscriptRolledOver`；同时检查 `internal_bus::is_lifecycle_critical`，不能只改消费者导致 dispatcher 丢事件。
- `commands/conversations.rs` 保留 stale/unbound session 恢复过滤及 expected-old CAS。Gemini/Cline alias 继续用 alias normalization；Claude `/clear` 是真实 transcript rollover，使用上游 continues/bind 路径，且旧解析结果不能覆盖已重绑定的新 id。
- `codex.rs` 采用 upstream `history_base`/revert 的迭代谱系处理和 visited 防环；移除旧递归的 8-hop 截断，避免丢失长 revert 链。保留本地完整 JSONL 记录读取、窗口 watermark、输出预算和内部消息过滤；没有现成的总文件读取字节硬上限。具体调用方修改见详细计划 Task 6，新旧测试均保留并适配。
- `acp_native.rs`、`grok.rs` 采用共享 `user_turn_block*` 附件投影，再施加本地可见文本过滤；保留 Turn 的 outcome/autonomous/generation 字段，避免附件存在却因无正文被丢弃。

### 4.4 通知与桌面事件入口

`acp-connections-context.tsx` 中本地批量 EventIngestor/gap recovery 与上游直接订阅/通知逻辑发生大段错位。保留本地唯一事件入口，把 `presentSessionNotice`、错误本地化、config verdict 和一次性通知归并进已验证 envelope 的 effect 阶段。

- 同一个事件只触发一次 toast/系统通知；snapshot hydrate 恢复状态但不重播通知；gap/replay 同时抑制声音、桌面通知和新增通知副作用。
- 保留 `attachError`、shared-session config conflict、observer alias、delivery failure 必须重启的保护；并入 upstream `errorLevel`/lastErrorLevel。
- 关闭/解绑时同时清理本地 discovery/handoff 与上游 connect error/turn failure；异步 connect 结果不能让已关闭 tab 复活。
- `session-failure-banner` 采用上游“retry incident 留在 dock，普通失败/notice 进入通知”的职责；本地 Codex compaction advisory 过滤保留在对应入口。告警证据继续可查看，不因 UI 改造丢失。
- `hasSettleableRetryIncident` 与 `hasActiveRetryIncident` 按实际语义合为一个使用约定，搜索全部调用后统一；不要留下两个近义 helper 各控制一半 UI。

### 4.5 会话组件与时间线

`conversation-detail-panel.tsx` 的上游大块不能复制回本地 wrapper。本地真正的生命周期位于 **`src/components/conversations/conversation-session-surface.tsx`**：在那里检查/移植 `trackConversationView`、`isReparentUnmount`、`reparentedViewRuntimeConversationId`、元数据 backfill、通知和 async task 操作，保留 popout/shared session/owner fence。

`conversation-runtime-store.ts` 以本地历史/流式分区、窗口加载、generation 失效机制为主：

- 移植 upstream `liveShowsReply` 判断，仅当 live 确实呈现回复时隐藏相应 persisted assistant。
- mid-turn steering user message 不成为新 round boundary；与后端 `in_flight_user_turn_id` stamping 一起收。
- 保留本地 stale prompt 检查、local/live 对齐和已完成 partition，避免重复回复或旧回合消失。
- 不叠加上游整套 WeakMap cache 与本地 cache；把新增影响因素放进本地 cache key/reset。reset 继续使在途 detail 请求失效，不能退回上游注释中承认存在的 generation-clear 竞态。
- `ai-elements-adapter` cache key 同时保留 reasoning_effort、completed_at、outcome fingerprint，并增加 source_turn_id；fork 操作锚点与 UI outcome 都必须刷新。

### 4.6 浏览器、终端与发布政策

- 接受上游 remote egress/tunnel、host addressing、`attach_engine_hooks`、macOS fallible profile configuration；保留本地截图、安全 gate、生命周期处理。bridge 的 `bridge_port` 变为可选值时使用上游 `filter_map`/`port_of`，不能硬 unwrap 远端模式。
- `lib.rs` 保留 `production_tauri_commands!` 宏；上游展开的 556 行注册列表只用于提取新增命令，重点核对 clipboard、browser remote/console 等 upstream diff，不替换整个 invoke handler。
- 默认 shell 继续由本地 `terminal::shell` 解析。模型保留 `effective_shell`，提供上游 UI 使用的 `resolved_shell` 时取同一解析结果；桌面和 Web handler 共用同一个 helper。不要再引入上游基于环境变量的第二套 shell 决策。
- `terminal/manager.rs` 上游新增的 poison-safe `lock_terminals` 可以接入；同一冲突臂内的旧 `resolve_shell` 与本地统一解析重叠，不整块复制。
- 服务器 updater 保留 fork 不支持原地 self-update/rollback 的政策；可以兼容 upstream blocker 的序列化/展示字段，但不能因新 helper 自动启用更新或回滚。保留政策测试，补充结构测试。
