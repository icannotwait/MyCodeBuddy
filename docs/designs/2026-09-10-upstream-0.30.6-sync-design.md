## Executive Decision

Merge **Codeg `v0.30.6` plus the commits already on `upstream/main` after that tag** into MyCodeBuddy by a no-ff merge on `sync/codeg-0.30.6`. Do not rebase published history. Do not merge on `main`.

Ship identity as **`0.30.6-mycodebuddy.1`**. Keep every fork invariant from `docs/UPSTREAM_SYNC.md`. Bring every upstream product capability in 0.30.3–0.30.6 (and the post-tag commits already on `upstream/main`) in, then adapt fork behavior around it.

This is the same class of work as the 0.30.0 integration: **92 conflicted files / 283 conflict blocks** as `git merge` writes them (the per-file `merge-file` probe splits the same regions into 308), not a version-bump PR. The 0.30.0 cookbook’s four verbs still apply: **TAKE_OURS / TAKE_THEIRS / MERGE_BOTH / REWRITE**.

## Problem

MyCodeBuddy last absorbed upstream at **Codeg `v0.30.2`** (`3ebdfed1`, merge `bc6ef1f7`). Upstream has since released 0.30.3–0.30.6 and kept moving. The fork also accumulated local commits that touch the same ACP, chat, backup, and settings files those releases edit.

A casual `git merge upstream/main` on `main` would stall in the same files the last full sync spent days on (`connection.rs`, `manager.rs`, `lib.rs`, backup/import, composer/canvas). This design freezes the baseline, the decisions, and the resolve order before anyone opens the merge.

## Goals

- Land current `upstream/main` (`fc92037f` or a newer tip fetched at merge time) on a dedicated sync branch.
- Publish identity `0.30.6-mycodebuddy.1` in `package.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` (`codeg` package), `src-tauri/tauri.conf.json`.
- Keep MyCodeBuddy branding, updater endpoints, Windows-only release policy, and OpenClaw deletion.
- Keep fork behavior: CompanionLease, `continue_delegation` + `resume_delegation` (six parent tools), session popout, ToolWatchdog, Grok autonomous / monitor-event handling, ConversationLinked `external_id`, Antigravity mcp skip, new-agent-default-disabled, Grok 1.0.25, CodeBuddy 2.148.0, `ConversationSessionSurface` extraction, event-ingestor delivery, `production_tauri_commands!` single command list.
- Keep upstream 0.30.3–0.30.6 product work (see Incoming Capabilities), including the 0.30.4 codeg-mcp broker **service** (Structural Decision 8).
- Update `docs/UPSTREAM_SYNC.md` examples from 0.30.2 to 0.30.6 after the merge is resolved.
- Write a post-merge cookbook (`docs/UPSTREAM_0.30.6_CONFLICT_RESOLUTION.md`) from the real merge, not from this probe.

## Non-Goals

- Rebasing MyCodeBuddy onto upstream, or merging on `main`.
- Restoring OpenClaw as a first-class built-in agent.
- Restoring `src-tauri/src/bin/codeg_server.rs`. Fork entry is `server_bin/main.rs`.
- Changing the six-tool parent delegation directory decided in the 0.30.0 sync.
- Re-adding the `tasks` / `automations` / `taskboard` companion tool groups or the `TaskProgress` / `TaskComplete` / `CreateAutomation` / `CreateWorkTask` broker messages the fork dropped in 0.30.0.
- Taking this probe’s block table as a substitute for the real merge. Re-run `merge-tree` if `upstream/main` or `main` moves before the branch is opened.
- Shipping a product release from the unresolved sync branch.

## Structural Decisions

These are locked before any conflicted file is edited. Same role as §3 in the 0.30.0 cookbook.

### 1. Identity

`<<<<<<< HEAD` keeps license, repository, homepage, updater URLs, installer names. Only the numeric prefix moves: `0.30.2-mycodebuddy.1` → `0.30.6-mycodebuddy.1`.

### 2. OpenClaw stays deleted; Pi joins the MCP app list

Upstream still carries `AgentType::OpenClaw`, `McpAppType::OpenClaw`, `parsers/openclaw.rs` and the OpenClaw MCP reader, but in this range it **adds** OpenClaw lines in exactly three files, all conflicted: `registry.rs` (pin `openclaw@2026.9.3`, Node floor `>=24.16.0 <25 || >=26.1.0` comment), `commands/mcp.rs` (`McpAppType::OpenClaw` in `ALL_MCP_APPS` and a `| McpAppType::OpenClaw` write-path arm), `mcp-settings.tsx` (`SCAN_ONLY_APP_LABELS.open_claw`). Drop those arms. Do not add `parsers/openclaw.rs`. No non-conflicted file gains an OpenClaw reference, so nothing slips in by auto-merge — still grep after resolve.

Adopt upstream’s `ALL_MCP_APPS` constant style in `commands/mcp.rs`. Upstream’s array is 15; the fork’s hand-written list (two copies) is 13 and omits both OpenClaw and Pi. The resolved array is **14**: every upstream member except OpenClaw.

**Pi is not just a constant entry on the fork.** The fork has `AgentType::Pi` but **no `McpAppType::Pi`** (`git grep McpAppType::Pi HEAD` → 0). Take upstream `#673` wholesale: the `Pi` enum variant, `read_pi_servers` / `read_pi_servers_at`, the `LocalMcpReader::new("pi", …)` entry, the write-path app-list guard, and `SCAN_ONLY_APP_LABELS = { pi: "pi" }` (drop `open_claw` from it). Keep the fork’s Antigravity / DeepSeek SSE guards; adopt upstream’s `tests::all_mcp_apps_is_exhaustive` (the fork has no equivalent) at 14 members.

### 3. Server binary path
