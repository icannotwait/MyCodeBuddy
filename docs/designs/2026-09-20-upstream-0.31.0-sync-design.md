## Executive Decision

Merge **Codeg `v0.31.0`** (`upstream/main` tip `aace536fe`) into MyCodeBuddy with a **no-ff merge** on branch `sync/codeg-0.31.0`. Do not rebase published history. Do not merge on `main` until the sync branch is green.

Ship identity as **`0.31.0-mycodebuddy.1`**. Keep every fork invariant from `docs/UPSTREAM_SYNC.md` and the 0.30.7 cookbook. Bring every upstream product capability from 0.30.8–0.31.0 in, then adapt fork behavior around it.

This is the same class of work as the 0.30.7 integration: **83 conflicted files / 272 conflict blocks** as `git merge` will write them — not a version-bump PR. The four verbs still apply: **TAKE_OURS / TAKE_THEIRS / MERGE_BOTH / REWRITE**.

---

## Problem

MyCodeBuddy last absorbed upstream at **Codeg `v0.30.7`** (merge `261f2520c` / cookbook merge parent chain). Upstream has since released **0.30.8, 0.30.9, 0.30.10, 0.31.0** (231 commits on `upstream/main` since the shared base). The fork also landed post-sync fixes (cold reconnect, Grok settle overlays, PR #16/#19 UI settle) that touch the same ACP / chat / connection files upstream edited.

A casual `git merge upstream/main` on `main` would stall in `connection.rs`, delegation companion/listener, `acp-connections-context.tsx`, identity files, and i18n. This design freezes the baseline, the decisions, and the resolve order before anyone opens the merge.

## Goals

- Land `upstream/main` @ `v0.31.0` (`aace536fe`) on `sync/codeg-0.31.0`.
- Publish identity **`0.31.0-mycodebuddy.1`** in `package.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` (`codeg` package), `src-tauri/tauri.conf.json`.
- Keep MyCodeBuddy / DrawCode branding, updater endpoints, Windows-oriented release policy, and **OpenClaw deletion**.
- Keep fork behavior: CompanionLease, six-tool parent delegation (`continue_delegation` + `resume_delegation` co-exist), cold-reconnect refetch, Grok settle overlays, `default_enabled=false`, server feature (`--features server`), `test:release` / low-memory cargo scripts.
- Keep upstream 0.30.8–0.31.0 product work (see Incoming Capabilities), including browser feature flags from Cargo.toml when they do not break headless server builds.
- Update `docs/UPSTREAM_SYNC.md` examples to 0.31.0 after resolve.
- Write post-merge cookbook `docs/UPSTREAM_0.31.0_CONFLICT_RESOLUTION.md` from the **real** merge, not from this probe.

## Non-Goals

- Rebasing MyCodeBuddy onto upstream, or merging unresolved work on `main`.
- Restoring OpenClaw as a first-class built-in agent.
- Changing the six-tool parent delegation directory decided in earlier syncs.
- Taking this probe’s block table as a substitute for the live merge. Re-run `merge-tree` if tips move before the branch opens.
- Shipping a product release from the unresolved sync branch.
- Silent force-push / rewriting published main history.

## Structural Decisions (locked before editing conflicted files)

### 1. Identity — MERGE_BOTH / TAKE_OURS on branding

- Version string everywhere: **`0.31.0-mycodebuddy.1`** (never bare `0.31.0`).
- `tauri.conf.json`: keep `productName` / `mainBinaryName` = `DrawCode`, `identifier` = `app.mycodebuddy`, publisher / homepage / license from ours.
- `package.json`: keep `license` / `repository` / `homepage`; merge scripts — **keep fork** `test:release`, `rust:check:low-memory`, `server:* --features server`; take upstream **browser:agent:*** scripts if absent on ours.
- `Cargo.toml` features: **MERGE_BOTH** — keep fork `test-utils` / `unmerged-upstream-helpers` / server feature wiring; adopt upstream `browser` / `browser-child` / `browser-smoke` feature flags so desktop browser work compiles when those features are enabled. Headless server build remains `--no-default-features --features server` (or current fork equivalent).
- `Cargo.lock`: regenerate after resolve (`cargo generate-lockfile` / build), then force `codeg` package version line to `0.31.0-mycodebuddy.1`. Do **not** `checkout --theirs` the whole lockfile as the only step.

### 2. OpenClaw stays deleted — TAKE_OURS

Any conflict that reintroduces `OpenClaw` / `open_claw` / `parsers/openclaw` → drop theirs. Grep after resolve; auto-merged leakage must be deleted.

### 3. Delegation protocol — MERGE_BOTH / REWRITE (fork six-tool directory)

Parent `tools/list` remains exactly:

1. `delegate_to_agent`
2. `register_simple_workflow`
3. `continue_delegation`
4. `resume_delegation`
5. `get_delegation_status`
6. `cancel_delegation`

Do not adopt upstream tool counts of 4/5. Do not add taskboard / automation tools to the companion allow-list. Take upstream **Ping** / service lifecycle improvements into `DelegationService` when present; keep CompanionLease and fork listener shapes.

### 4. Registry pins — TAKE_THEIRS when newer

Agent distribution pins in `registry.rs`: prefer **upstream newer versions**. Keep fork-only agents and `default_enabled -> false` for newly registered agents. CodeBuddy / route pin constants must agree with registry.

### 5. ACP connection + FE hydrate — REWRITE (fork-base for settle paths)

For `connection.rs`, `acp-connections-context.tsx`, `use-connection*.ts`, `conversation-runtime-store.ts`:

- Skeleton / settle / cold-reconnect / Grok overlay behavior: **fork-base REWRITE**.
- Port upstream: temp-dir isolation, AF_UNIX budget, model display naming, ask-card protocol hooks, streaming perf hooks, deep-link session attach.
- Misaligned conflict blocks (git pairs unrelated hunks): **TAKE_OURS on the wrong locus**, port theirs into the real arm (same rule as 0.30.7 §3.4).

### 6. i18n — MERGE_BOTH

Union keys; DrawCode / MyCodeBuddy product strings stay ours; take upstream new keys. After resolve: all locales same leaf-key set; no `<<<<<<<`; valid JSON.

### 7. Parsers — MERGE_BOTH / REWRITE

OpenCode deep-adapt and Cline connect/auto-approve fixes come from upstream — take them. Keep fork DeepSeek / visibility helpers where still present. Snapshot tests: regenerate after resolve if fixtures change.

### 8. Server / web — MERGE_BOTH

Keep fork `codeg-server` feature flags and web handler registration patterns. Take upstream new routes/handlers. Do not resurrect deleted upstream-only bins the fork replaced.

## Resolve Order

1. Identity (`package.json`, `Cargo.toml`, `tauri.conf.json`, README/docker-compose branding bits).
2. `Cargo.toml` features + `lib.rs` / `app_state.rs` module wiring (so the crate graph compiles).
3. Registry + parsers (pins and OpenClaw grep).
4. Delegation (`tool_schema.json` → companion → listener → service/transport → e2e tests).
5. `connection.rs` + `commands/acp.rs` + terminal/question/preflight/mod.
6. Frontend contexts/hooks/stores (connections → workspace → runtime store → chat/message components).
7. i18n locales (scripted key union if available).
8. Server/web/commands leftovers.
9. `Cargo.lock` regenerate + version pin.
10. Compile / test loop; write cookbook from actual resolutions.

## Verification Gate (must pass before merge to main)

From `AGENTS.md` / prior sync practice (adjust to scripts present after merge):

1. `pnpm test:release` — version / URL identity.
2. Frontend: `pnpm lint` / `pnpm test` (or project’s documented vitest gate).
3. Rust: `cargo check` / `cargo test` for lib + server feature matrix used in CI (`.github/workflows/test.yml`).
4. Grep gates: no `<<<<<<<`; no `OpenClaw` runtime wiring; version string `0.31.0-mycodebuddy.1` consistent; parent delegation tool list length == 6.
5. Smoke (local deploy optional): `codeg-server` starts; one ACP connect_or_attach; UI loads a conversation.

No “done” claim without fresh command output (verification-before-completion).

## Merge-to-main Policy

- Work only on `sync/codeg-0.31.0` (or PR branch from it).
- Open PR into `main`; CI green; then merge (no-ff preferred).
- After merge: update `docs/UPSTREAM_SYNC.md`; commit cookbook `docs/UPSTREAM_0.31.0_CONFLICT_RESOLUTION.md`.
- Do not push/merge until verification gate is green.
