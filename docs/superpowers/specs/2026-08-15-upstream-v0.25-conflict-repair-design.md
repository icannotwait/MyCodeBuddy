# Upstream v0.25 Conflict Repair Design

Date: 2026-08-15

Status: Approved in conversation on 2026-08-15.

## Context

Branch `merge/upstream-v0.25.0` mechanically merged upstream v0.25.0 into
MyCodeBuddy. The index is clean, conflict markers are gone, and CI passes, but
the merge selected incompatible halves of several conflicts. Frontend contracts
from one parent are paired with backend implementations from the other, and
some security fixes were replaced by the behavior they were intended to remove.

This repair follows `docs/UPSTREAM_SYNC.md`: preserve functional fork changes,
then adapt incoming upstream behavior around them instead of silently dropping
either side. The upstream parent of merge commit `3b2eece4` is the reference for
the missing v0.25 behavior; the current branch remains authoritative for fork
features added around it.

## Goals

- Restore every confirmed security fix lost during conflict resolution.
- Make every retained frontend transport call available in both Tauri and Web
  runtimes.
- Support both fork and upstream history-window coordinate systems.
- Restore ACP wire and DTO compatibility for adapters, boolean configuration,
  permission metadata, and concurrent permission requests.
- Update the built-in agent registry to the reviewed v0.25 releases while
  preserving MyCodeBuddy-specific launch behavior.
- Make workspace file transfer honor user-authorized folder links without
  weakening traversal protection for arbitrary symlinks.
- Preserve the fork's user-intent draft-opening contract in the new workspace
  folder dialog.
- Install the already-implemented server compression policy.
- Add regression coverage that fails when either runtime or either side of a
  cross-language contract drifts again.

## Non-Goals

- Restoring OpenClaw. `docs/UPSTREAM_SYNC.md` explicitly preserves its deletion.
- Replacing fork branding, release metadata, update endpoints, installers, or
  Windows-only release policy.
- Rewriting ACP connection architecture or consolidating its large modules.
- Changing the public meaning of the fork's existing user-turn history options.
- Making arbitrary repository symlinks trusted. Only folder links explicitly
  recorded by the user are authorized.
- Adding new product features beyond the behavior already present in one merge
  parent or already promised by the current frontend.

## Selected Strategy

Repair each subsystem against the upstream reference implementation, then adapt
it to current fork call flows. Do not copy whole files from either parent. Each
subsystem receives a focused regression test before production code changes.

The work is split into independently testable units:

1. Pi project trust.
2. ACP host-tools and Codex launch security.
3. Permission request serialization.
4. Conversation history windows and transport registration.
5. Git transport commands.
6. ACP DTO, boolean configuration, permission metadata, and registry versions.
7. Folder-link-aware workspace transfers.
8. Draft opening and Web compression.
9. Cross-runtime parity and full regression verification.

## Pi Project Trust

### Required behavior

Codeg must never grant Pi project trust as a side effect of connecting. Pi
project resources can include `.pi/extensions` and project packages whose code
runs during startup, before the first prompt. Trust is therefore an explicit
user decision, not a convenience default.

Restore the upstream trust model:

- enumerate trust-requiring resources for a workspace;
- resolve the nearest inherited Pi trust decision;
- expose the deciding path and trust-file path to the UI;
- store Codeg's acknowledgement of pre-existing grants separately from Pi's
  `trust.json`;
- serialize writes with Pi's lock-file protocol;
- provide query, grant, deny, revoke, acknowledge, and list operations;
- block launch when a real trust grant covers executable project resources but
  has not been acknowledged in Codeg; and
- leave undecided or denied workspaces launchable because Pi skips their local
  project resources.

Remove `seed_pi_workspace_trust` from the launch path. The legacy
`PI_ACP_TRUST_WORKSPACE` key may remain reserved for configuration migration,
but it must not grant trust.

### Runtime surface

Register all four commands in both Tauri and Web modes:

- `acp_pi_project_trust_state`
- `acp_pi_set_project_trust`
- `acp_pi_acknowledge_project_trust`
- `acp_pi_list_trust_entries`

The Web handlers call the same `_core` functions as Tauri. No runtime may have a
different trust policy.

### Failure policy

Unreadable or malformed trust data fails closed for writes and for an existing
unacknowledged grant. It must never be replaced with an empty object. A missing
file is an empty trust store. Lock contention returns an actionable error and
does not partially update either trust or acknowledgement state.

## ACP Execution Security

### Host-tools policy

Resolve `HostToolsPolicy` once from the complete per-agent runtime environment
when the connection is spawned, then carry the immutable result through the
connection lifetime.

When the policy is `Default`:

- preserve the current per-agent capability behavior, including Grok's terminal
  exception;
- Codeg services its filesystem and terminal request handlers; and
- delegation remains controlled by the existing delegation setting.

When the policy is `Agent`:

- advertise neither filesystem nor terminal capabilities;
- reject direct calls to every withheld method with method-not-found;
- withhold the Codeg delegation tool group so a sibling agent cannot bypass the
  selected agent's sandbox; and
- retain non-executing companion groups such as feedback, questions, session
  information, and reporting.

The handler rejection is required even when the capability was not advertised:
capability negotiation alone is not an authorization boundary.

### Codex initial mode

Use the current `CodexSandboxSettings` parser to map effective root
`sandbox_mode` and `approval_policy` values to codex-acp presets:

- `read-only` -> `read-only`;
- `workspace-write` -> `agent`;
- `danger-full-access` plus `never` -> `agent-full-access`;
- `danger-full-access` with any approval-requiring policy -> `agent`; and
- missing, malformed, or profile-shadowed settings -> no inferred preset.

Inject the inferred value as `INITIAL_AGENT_MODE` at Codex process launch.
Preserve a non-empty value explicitly supplied in the agent runtime environment.
An explicit session mode or config option applied after connect remains higher
priority than launch inference.

## Permission Request Queue

Replace the plain responder map with a connection-scoped FIFO permission queue.
The queue owns responder lifetime and visible-card ordering as one invariant:
every live responder is either the displayed request or in the waiting deque.

Admission behavior:

- the first request is emitted immediately;
- later concurrent requests are retained without emitting a second card;
- the visible event reports how many further requests are queued; and
- queue-depth changes update the current card without changing its identity.

Resolution behavior:

- only the displayed request can be answered through the ordinary UI flow;
- a valid answer settles its responder, emits `PermissionResolved`, and promotes
  the next request atomically;
- unknown or duplicate answers are harmless errors/no-ops and never promote a
  second time; and
- promotion is FIFO.

Teardown behavior:

- user cancel, watchdog cancel, disconnect, fork transition, failed turn, and
  normal terminal finalization drain all responders;
- each displayed card receives a compensating resolved event; and
- draining and a following turn-complete event are ordered under the same queue
  lock so a racing admission cannot be hidden by turn cleanup.

Snapshots expose only the displayed request and its queued count. The frontend
continues to keep one card slot; the backend queue makes that representation
correct.

## Conversation History

The two window systems solve different compatibility requirements and both are
retained.

### User-turn window

The fork fields remain supported:

- `historyUserTurnLimit`
- `historyBeforeTurnId`

They select conversational rounds and continue populating `history_window`.

### Index window

The upstream fields are restored:

- `tailTurns`
- `fromIndex`

They select exact transcript indices and populate `turns_offset`, `turns_total`,
prefix timestamps, and prefix fingerprints used by the live runtime store.

### Selection rules

- `tailTurns` and `fromIndex` are mutually exclusive.
- Index-window fields and user-turn-window fields are mutually exclusive in one
  request. Invalid combinations return `invalid_input`; they do not silently
  choose one coordinate system.
- No window fields preserves the legacy full response.
- Live pending-message correlation and delegation metadata are applied before
  the final index slice so metadata and indices describe the same transcript.

Restore `get_folder_conversation_turns` as the reverse-infinite-scroll page API
in both runtimes. It returns the upstream seam-proof metadata and never performs
auto-title or sidebar side effects.

## Missing Git Commands

Restore the upstream core operations and expose them through both runtimes:

- `git_update_branch` updates a checked-out branch with the existing pull path,
  fast-forwards another local branch from its upstream without checkout, or
  refreshes a named remote-tracking ref.
- `git_remove_worktree` validates the selected worktree, removes it, optionally
  deletes its branch, honors the explicit force flag, and re-parents/removes the
  corresponding folder record through existing folder services.

Both commands reuse the existing credential and Git error mapping. They must
return structured conflict results where the surrounding Git UI already expects
them, and must not turn destructive fallback behavior on implicitly.

## ACP Contracts and Registry

### Response DTOs

Restore structured adapter information in `PreflightResult` and
`is_acp_adapter` in both full and lightweight agent status DTOs. Derive these
values from the registry's adapter relation rather than duplicating agent lists
in the frontend.

Restore opaque permission-option metadata end to end. The backend forwards ACP
`_meta` without interpreting it; the frontend remains responsible for localized
rendering of permission-change descriptions.

### Boolean config options

Retain `unstable_boolean_config` and add the Rust mirror variant. Mapping must
preserve boolean options rather than filtering them out. The frontend continues
to store preference values as strings, but the ACP wire encoder sends a real
boolean for a boolean option and a value-id string for a select option.

Unknown future config kinds are stripped from raw session responses before
typed deserialization so one new optional selector cannot terminate the whole
agent connection. Known kinds are exactly `select` and `boolean` for this schema
version.

### Registry versions

Adopt the reviewed upstream v0.25 versions for retained built-ins, including the
adapter releases required by the restored contracts. Preserve MyCodeBuddy's
Codex distribution environment and route policy. Preserve OpenClaw deletion.

Hermes moves to the upstream 0.20.1 npm bridge so the installed runtime matches
the 0.20 provider registry already present in the settings implementation. The
old 0.19 uvx-specific assumptions and version assertions are removed from the
built-in Hermes entry; generic uvx support remains for custom distributions.

Version tests pin package, command, Node floor, binary URLs, and platform
availability so a future merge cannot silently retain an earlier whole table.

## Folder-Link-Aware Workspace Transfers

Continue rejecting `..`, absolute components, and arbitrary symlink traversal.
The process-global folder-link registry is the only additional authority.

### Uploads

Walk the target path segment by segment before creating directories. For each
existing symlink:

- canonicalize it;
- require the resolved target to be authorized for the canonical workspace
  root; and
- continue validation from the resolved real path.

Return the resolved, link-free path and use it for directory creation and final
file commit. Do not validate one path and then write through the original
symlink path, which would reintroduce a swap race.

### Downloads

Canonicalize root and target. Accept the target when it is inside the canonical
root or inside a registered linked target belonging to that root. File and
directory download tickets use the same predicate. ZIP traversal still skips
unregistered nested symlinks.

Removing a folder link immediately revokes transfer access because the registry
is updated by the existing link command before the next operation.

## Draft Opening and Compression

The workspace-folder creation flow is a user-intent open. It must call
`openFolderWithDraft`, not the silent store primitive. Manage-existing-folder
mode does not create another draft.

Install `web::compression::compression_layer()` as the outermost router layer.
Its existing allowlist remains authoritative: JSON and static text may compress,
while downloads retain content length and event streams remain unbuffered.

## Test Strategy

Every production behavior change follows a red-green cycle.

### Focused Rust tests

- Pi resource detection, inherited decisions, acknowledgement, locking, launch
  block, and explicit write/revoke behavior.
- Host-tools capability shape, handler refusal error, delegation gating, and
  Codex initial-mode mapping/precedence.
- Permission queue admission, FIFO promotion, queued depth, duplicate answers,
  and every drain path.
- Combined history selector validation, index metadata, user-turn compatibility,
  and history page seams.
- Git branch update and worktree-removal validation/core behavior.
- Adapter DTO projection, boolean mapping/wire encoding, permission metadata,
  unknown-kind filtering, and registry version pins.
- Authorized upload/download link traversal and revocation, while arbitrary
  symlinks remain rejected.
- Router response compression for an eligible JSON body and exclusion for a
  binary/download response.

### Focused frontend tests

- Workspace folder creation opens exactly one draft for the selected folder.
- Pi trust surfaces call real transport names and handle blocked-launch state.
- Boolean config controls render and submit string preferences that the backend
  converts at the wire boundary.
- Windowed history selects the correct option family and requests older pages.

### Contract and parity tests

Add a test-owned manifest of frontend commands introduced by this repair and
assert that each is registered in the Tauri invoke handler and Web router. The
test covers the seven missing commands, including all four Pi trust commands,
as one explicit contract; it is not a brittle parser of every string in
`api.ts`.

Add representative JSON fixtures for `PreflightResult`, `AcpAgentInfo`,
`AcpAgentStatus`, boolean config options, permission option metadata, and
windowed conversation responses. Rust serialization tests and TypeScript
consumer tests use the same required field names and discriminators.

### Final verification

Run the repository-required suites after focused tests are green:

- `pnpm eslint .`
- `pnpm test`
- `pnpm test:release`
- `pnpm build`
- `cargo fmt --check`
- desktop `cargo check`, library tests, full tests, and clippy with test-utils;
- server check, tests, and clippy;
- codeg-mcp check and clippy; and
- `git diff --check` plus conflict-marker and unresolved-index scans.

Long Rust commands follow the repository's 30-60 second wait policy.

## Acceptance Criteria

- Connecting Pi cannot create or enlarge a trust grant.
- A Pi workspace with executable trusted resources and no Codeg acknowledgement
  is blocked before the Pi process starts.
- Enabling agent-hosted tools changes initialize capabilities, refuses Codeg
  file/terminal handlers, and disables delegation for that connection.
- A Codex read-only configuration launches with the read-only ACP preset unless
  a stronger explicit user choice overrides it.
- Three concurrent permission requests can all be answered in FIFO order with
  only one visible card at a time, and teardown leaves no blocked responder.
- All seven previously missing frontend commands work in Tauri and Web modes.
- Both history coordinate systems return the documented metadata, and mixed
  requests fail explicitly.
- Rust responses satisfy every retained TypeScript ACP field and discriminator.
- Built-in versions match the reviewed v0.25 table, with Hermes configuration
  and installed runtime on the same release family.
- Upload and download work through a registered folder link and fail through an
  unregistered symlink.
- Opening a new workspace folder creates its draft tab.
- Eligible server responses are compressed and excluded responses are not.
- Focused and full repository verification passes without warnings or snapshot
  changes that have not been reviewed.
