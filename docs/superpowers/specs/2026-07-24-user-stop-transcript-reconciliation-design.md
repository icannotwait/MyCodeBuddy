# User Stop Transcript Preservation and Reconciliation Design

Date: 2026-07-24  
Revised: 2026-07-26 (Round 4e — baseline map rebased onto HEAD partial implementation)

Status: Design approved (Round 4e document review group); implementation plan next

## Summary

Preserve stop-time live content and **best-effort** recover rollout-persisted
content for a user-stopped Codex turn. A user Stop must remain a terminal
action: it never resumes or resends the prompt. The UI commits every live block
it currently owns, renders interruption as typed turn metadata rather than
assistant prose, and then performs a bounded persisted-detail reconciliation
once the Codex rollout contains a matching `turn_aborted` record under the
append-order fence contract below.

The matching abort record is the **identity fence** (and the practical
terminal-order signal under Codex append-order). Codeg must not replace a
correct live response with a detail read taken before that fence, which avoids
reintroducing the transcript-flush race documented in the existing
`completeTurn` path. Full bit-for-bit recovery of every pre-stop token is not
a formal guarantee when the abort line is readable before trailing flush.

## Incident Evidence

Conversation 1249 was interrupted by an explicit user Stop after substantial
work had already been produced. Between the initiating user message and the
first abort, the original Codex rollout contains:

- 32 visible `agent_message` records;
- 222 reasoning records; and
- 139 tool calls.

Loading the same conversation through the existing cold parser restored 300
assistant sub-turns, including 32 text blocks, 129 grouped thinking blocks, and
139 tool-use/result pairs. The content was therefore not deleted from disk.

The live path instead ended with only `*Conversation interrupted*` visible:

- The pinned Codex ACP adapter
  (`@agentclientprotocol/codex-acp@1.1.7`, source at
  `src-tauri/vendor/codex-acp`) implements
  `CodexAcpServer.notifyConversationInterrupted`, which emits
  `*Conversation interrupted*` via `createAgentTextMessageChunk` as an ordinary
  `agent_message_chunk` (see `src-tauri/vendor/codex-acp/src/CodexAcpServer.ts`).
- `conversation-runtime-store.completeTurn` /
  `completeLiveTranscriptTurn` intentionally promotes only the current
  in-memory live buffers and does not refetch persisted detail (documented
  ~8 ms flush race at `conversation-runtime-store.ts`).
- The Codex cold parser correctly preserves the rollout's `agent_message`,
  reasoning, and tool records. **Historical incident (pre-landing):** the
  parser ignored `event_msg.turn_aborted`. **Current HEAD** already has a
  `turn_aborted` arm and tests; Round 4e gaps vs this design (display-only
  null-id outcome, etc.) are listed under Implementation Baseline.

The marker is not a collapsed summary and cannot reveal hidden content. It is
normal assistant prose generated by the adapter. The production evidence does
not identify the exact point at which the earlier live buffer was missed or
reset, so this design does not depend on an unproven tab-switch, reconnect, or
duplicate-status mechanism.

## Goals

1. Keep all locally observed text, thinking, tools, and results **visible
   immediately after Stop** (synchronous live/optimistic promotion). This is a
   stop-time visibility guarantee, not a guarantee that every ACP-only live
   block has a durable parser twin after fenced reconcile.
2. **Best-effort** recover earlier streamed records that are present in the
   rollout but absent from the final live buffer, **when the matching abort
   fence becomes readable before a newer prompt invalidates the cancellation
   session**, under the append-order fence contract (not a formal completeness
   proof).
3. Represent interruption as typed terminal metadata, never as assistant text
   pretending to summarize hidden output. Live path always shows the footer when
   `user_stop` is accepted; cold path attaches a generic interrupted outcome
   when a readable abort is present (with or without matchable `provider_turn_id`
   for display — see Parser Changes). Exact non-empty `provider_turn_id` is
   required only to **authorize destructive** coordinator replace.
4. Prevent any automatic pre-fence **or pre-envelope** persisted read from
   replacing richer live content (owner reconcile, viewer sync, background
   terminal sync, status-edge delegate terminal sync). Soft fence starts at
   Stop click; full `CancelCompletionKey` continues the suppress until cleared.
5. Make completion and reconciliation idempotent across duplicate delivery,
   tab switching, viewer attachment, and stale detail responses.
6. Keep ordinary successful completion on its current no-refetch path.

## Non-Goals

- Automatically continuing, retrying, or resending the interrupted prompt.
- Covering terminal disconnects, process exits, application shutdown, parent
  cancellation, or other non-user interruption sources.
- Changing idle Cancel behavior. An idle Cancel continues to emit no synthetic
  `TurnComplete`.
- Diagnosing the single exact live-buffer-loss mechanism without new runtime
  instrumentation.
- Replacing the general ACP event, connection ownership, or transcript watcher
  architecture.
- Adding a database migration. Cold interruption metadata is derived from the
  rollout during parsing.
- Refetching conversation detail after every normal turn.
- Guaranteeing automatic recovery when the user (or queue flush) starts a new
  prompt before the abort fence is observed. In that case the live-promoted
  content and interruption footer remain; full recovery is via Manual Reload
  or cold open once the abort record exists. Queue flush timing after Stop is
  intentionally unchanged.

## Alternatives Considered

### Remove Only the Synthetic Marker

Deleting `*Conversation interrupted*` prevents a misleading final assistant
message, but it does not recover streamed blocks already missing from the live
buffer. A response could still end blank or partial.

### Immediately Replace From Persisted Detail

An unconditional `refetchDetail(..., { preserveLive: false })` after
`TurnComplete` is simple, but it repeats a known data-loss race. Existing code
documents hardware evidence where the final assistant record was only 8 ms
ahead of `TurnComplete`; a detail read in that window can omit trailing records
and overwrite the already-correct local projection.

### Selected: Typed User Stop With Abort-Fenced Reconciliation

Commit the live response synchronously, identify the user-stop completion and
the provider turn exactly, and reconcile only after the parser observes the
matching durable abort record. This repairs both full and partial live buffers
without weakening normal completion or trusting an arbitrary delay as proof of
persistence.

## Semantic Contract

### User-Stop Origin

**ADD** optional closed fields on `AcpEvent::TurnComplete` (Rust + TS mirror):

```text
termination_source?: "user_stop"
provider_turn_id?: string
```

Wire rules:

- Both fields use `#[serde(default, skip_serializing_if = "Option::is_none")]`
  on Rust and optional properties on TS.
- Absent fields = legacy behavior: complete as today, **no** cancellation
  reconciliation.
- Only the backend branch that resolves
  `TurnFinalizationDisposition::UserCancelled` /
  `finalize_active_user_cancel` sets `termination_source = "user_stop"`.

Emit sites that must **not** set `termination_source` (non-exhaustive checklist
for implementers and tests):

1. `finalize_active_watchdog_cancel` (also uses `stop_reason: "cancelled"`).
2. `emit_ordinary_turn_finalization` / natural end (including upstream
   `cancelled` mapped through `NaturalEnd`).
3. `SuspensionFailed` ordinary finalization.
4. Idle Cancel (`ConnectionControl::Cancel` when no active prompt) — emits no
   `TurnComplete` at all.

A generic `stop_reason = "cancelled"` is never sufficient to start this design's
reconciliation.

### Exact Provider Correlation

#### Adapter (vendor)

On Codex `turn/started`, the adapter already stores
`sessionState.currentTurnId = notification.params.turn.id`.

**ADD:** emit a metadata-only ACP session update at that boundary using the
existing helper:

```text
session_info_update._meta.codex.activeTurnId = provider_turn_id
```

On Codex `turn/completed` (and any path that clears `currentTurnId` today),
clear local adapter state as today. Do **not** emit the synthetic
`*Conversation interrupted*` agent chunk from
`notifyConversationInterrupted` on interrupted-prompt paths; simply omit that
call (or make it a no-op). Model-authored text containing those words remains
valid; Codeg must not add a global string filter.

#### Rust connection

**ADD** connection-local active provider turn id state (not DB-persisted):

- Accept `_meta.codex.activeTurnId` from `SessionInfoUpdate` only while the
  connection's own turn is in flight (`turn_in_flight` / equivalent generation
  guard), including while a delegation suspension lease is held if the same
  prompt turn is still active.
- Ignore late metadata after terminal finalization so an old id cannot leak
  into the next prompt.
- On `UserCancelled`, **snapshot** the stored id into
  `TurnComplete.provider_turn_id` **before** clearing it.

#### Cancel vs metadata readiness

The in-turn loop uses a biased `tokio::select!` that can finalize Cancel before
a ready `session.read_update()` carrying `activeTurnId` is drained.

**ADD:** before snapshotting the provider id on user Cancel, perform a
**bounded non-blocking drain** of already-ready session updates so a turn id
that has already arrived on the wire is not lost solely to select bias. Prefer
reusing the existing ready-update machinery (`ReadyUpdateSource` /
`drain_ready_in_prompt_updates` / zero-timeout `try_next_ready` patterns in
`connection.rs`) rather than inventing a new wait loop. This is not an unbounded
wait for Codex; it only harvests updates already ready at cancel time.

If cancellation still wins before any provider turn id exists, Codeg still
commits the live buffers and displays interruption, but performs **no**
destructive persisted replacement. There is no proven matching fence without
an id.

#### Rollout fence key

The Codex rollout's `event_msg` with `payload.type == "turn_aborted"` carries
`turn_id` (nullable string) and `reason`. That `turn_id` is the only accepted
match for a persisted cancellation fence. Timestamps, message counts, the
latest turn, and literal text are not correlation keys.

Do **not** treat the text-only user `response_item` envelope `<turn_aborted>`
as a fence; the detail parser already ignores those internal envelopes.

### Typed Turn Outcome

**ADD** optional terminal metadata on `MessageTurn` (Rust + TypeScript):

```text
TurnOutcome {
  status: "interrupted"
  stop_reason: "cancelled"   // live path and reconciled result both normalize here
  source?: "user_stop"
  provider_turn_id?: string
  // Optional display timing; see Timing rules below
  completed_at?: string      // ISO-8601, same convention as MessageTurn.completed_at
  duration_ms?: number
}
```

Deserialization defaults to absent, preserving compatibility with every
existing parser and cached detail payload.

`TurnOutcome` is not a `ContentBlock::Text` and is excluded from assistant
copy, Markdown parsing, and model-visible transcript content. The timeline
renderer presents it as a compact localized footer after the affected response
group. It must not create a message bubble, accordion, or summary card.

#### Current-turn boundary (outcome attachment)

Define the cancelled turn using the completion identity, not “last assistant
in the whole session”:

1. Capture `activeTurnToken` (frontend runtime; may be null for pure viewers)
   and `provider_turn_id` (when known) at acceptance.
2. On synchronous completion:
   - If the promoted streaming/live assistant turn(s) for **this** completion
     include at least one assistant turn created after the current prompt
     boundary, attach the outcome to the **last such** assistant turn.
   - If the live buffer produced **no** assistant turn for this prompt
     (empty shell; today's promotion may omit empty assistants), **append** a
     deterministic outcome-only assistant turn keyed by the completion
     identity (e.g. synthetic id derived from
     `(connection_id, completion_seq)` or `provider_turn_id`). Never stamp
     outcome onto a prior prompt's last assistant.
3. On cold parse: the rollout exposes `provider_turn_id` on `turn_aborted`
   itself, **not** on every preceding assistant/tool record. Operational
   attachment boundary is therefore **positional**: attach outcome to the last
   assistant turn **after the last visible user message and preceding the abort
   record** (search from last `User` turn). This is **not** full provider-turn
   identity correlation for multi-user-input provider turns (elicitation,
   steering). Document that limitation; fixtures must cover empty current shell
   and prior-prompt isolation. If none, create an outcome-only assistant turn
   after the last visible user turn.
   - Live synthetic outcome-only id: `outcome-${connectionId}-${completionSeq}`
   - Cold synthetic outcome-only id: `assistant-outcome-${index}` (parser-stable
     positional). Live and cold ids need not match; fenced
     `RECONCILE_CANCELLED_TURN` replaces detail wholesale.

#### Timing rules

- Prefer abort-visible timing for the footer when available:
  - `completed_at`: ISO string from the enclosing rollout record's top-level
    `timestamp` when parsing `turn_aborted` (not a fabricated epoch field on
    the payload).
  - `duration_ms`: copy only if present on the rollout envelope or sibling
    fields; the minimal protocol shape is `{ turn_id, reason }` and may omit
    duration.
- `MessageTurn.completed_at` / `duration_ms` remain the turn-level fields they
  are today. `TurnOutcome` timing is abort/display metadata and must not
  require inventing protocol fields that do not exist.
- Live path may set `completed_at` to acceptance wall time and leave
  `duration_ms` unset; reconcile overwrites timing from the fenced parse when
  present.

#### stop_reason normalization

Live envelope uses `stop_reason: "cancelled"`. Parser-derived outcomes also
normalize to `"cancelled"` for footer copy consistency (even if rollout reason
is the string `"interrupted"`). Footer localization keys off
`status === "interrupted"` + optional `source`, not competing free-form strings.

## Adapter Changes

For a Codex turn completed with status `interrupted` in the vendor adapter:

1. stop calling `notifyConversationInterrupted` (no `*Conversation interrupted*`
   agent message chunk);
2. return `stopReason = "cancelled"` as today; and
3. map `turn/started` to the metadata-only
   `_meta.codex.activeTurnId` session-info update (via
   `createCodexSessionInfoUpdate`).

The turn-identity update produces no transcript content and remains excluded
from the backend's `is_agent_output_update` classifier (`connection.rs`), which
already excludes `SessionInfoUpdate`.

## Parser Changes

The Codex parser **ADD**s recognition for:

```json
{
  "type": "event_msg",
  "payload": {
    "type": "turn_aborted",
    "turn_id": "provider-turn-id-or-null",
    "reason": "interrupted"
  }
}
```

Protocol notes (normative):

- Minimal generated shape is `{ turn_id: string | null, reason: TurnAbortReason }`
  where `TurnAbortReason = "interrupted" | "replaced" | "review_ended"`.
- Optional extra fields (e.g. `duration_ms`, `started_at`) may appear on some
  rollouts; copy when present, never require them.
- Enclosing JSONL record `timestamp` (if present) is the source for
  `TurnOutcome.completed_at` conversion to ISO.

On this record the parser:

1. flushes any pending reasoning for that provider turn;
2. preserves every previously parsed assistant/tool record;
3. **if** `reason === "interrupted"` **and** `turn_id` is a non-null
   non-empty string: attaches an interrupted `TurnOutcome` **with**
   `provider_turn_id` to the last assistant after the last visible user turn
   preceding the abort (or creates an outcome-only assistant turn when
   necessary). This outcome both displays interruption and **authorizes**
   coordinator match;
4. **if** `reason === "interrupted"` **and** `turn_id` is null/empty: still
   attach a **display-only** interrupted outcome (`status: interrupted`,
   `stop_reason: cancelled`, **no** `provider_turn_id`) so cold open/reload
   keeps a typed footer; the runtime coordinator **must not** treat this as a
   matchable fence;
5. if `reason` is `"replaced"` or `"review_ended"`: do **not** attach an
   interrupted outcome and do **not** authorize cancellation reconciliation;
6. exposes the outcome in `DbConversationDetail` as part of the normal parsed
   turn list.

Seeing the matching complete `turn_aborted` JSONL record is a **readable
append-order fence**, not an `fsync` durability proof. A truncated or malformed
final line does not produce an outcome and therefore cannot authorize
replacement.

#### Fence completeness contract (normative v1)

**Chosen contract (not optional):** recovery is **best-effort under Codex
append-order**, not a formal completeness proof.

1. Codeg treats a complete JSONL `event_msg.turn_aborted` line with
   `reason === "interrupted"` and non-empty `turn_id` as the **identity fence**
   that authorizes coordinator apply of the **parser projection available on
   that read**.
2. Working assumption (not a pinned upstream formal guarantee): Codex normally
   appends in-scope assistant/reasoning/tool/result records for that turn
   **before** the abort event (append-order; not fsync). When that holds,
   first-match apply restores missing live content from the rollout.
3. **v1 does not implement** a mandatory stable double-read / watermark.
   Delays (100/300/1000 ms) are churn control only and never authorize apply.
4. If in-scope content is ever appended **after** the abort line, first-match
   apply can miss trailing records. That residual is **accepted and named**
   (see Risks); AC2 promises best-effort recovery under the append-order
   assumption, not absolute completeness.
5. Tests **must** include: (a) pre-abort multi-block survival; (b) truncated
   abort line → no fence; (c) a fixture with a relevant post-abort in-scope
   record documenting v1 first-match apply behavior (may miss the post-abort
   record).
6. Exact match of `provider_turn_id` authorizes identity; it does **not** prove
   live/cold parity for every ACP-visible live-only block.

Parser tests use the repo's insta snapshot workflow when snapshots churn
(`cargo insta review` / `INSTA_UPDATE=auto`).

## Frontend Runtime Design

### Dual-path completion (end-to-end)

Today:

- Owner tabs often promote on the connStatus prompting→idle edge via
  `completeLiveTranscriptTurn` **without** envelope fields.
- `turn_complete` envelopes are handled in `acp-connections-context.tsx`
  (permissions / connected / notify); background listeners no-op promotion for
  open owner tabs.

**Required split:**

0. **Stop-time soft fence + ownership snapshot (mandatory, before envelope):**
   When the user issues Stop / `ConnectionControl::Cancel` against an active
   prompt, the frontend **must immediately** (before awaiting backend
   `TurnComplete`):
   - snapshot ownership `(activeTurnToken, cancelGeneration)` keyed by the
     **runtime session key** (may be negative for draft-originated tabs);
   - install a **soft cancel fence** on that runtime session that suppresses
     automatic destructive detail commits (`preserveLive: false` /
     `FETCH_DETAIL_SUCCESS` apply, viewer nudge, delegate terminal sync,
     status-edge post-promotion destructive sync).

   ##### Soft-fence state machine (normative)

   | State | Enter | Suppress auto destructive? | Exit |
   | --- | --- | --- | --- |
   | `soft_fence_active` | Stop click with active prompt | **Yes** | → `pending_cancel` when full key can start coordinator; → `owner_preserve` on missing envelope age-out, missing provider id, provider id + unbound detail id, Branch B apply, or retry exhaustion; → clear only on explicit exits |
   | `pending_cancel` | Accepted `user_stop` + non-empty `provider_turn_id` + positive detail id | **Yes** | Success Branch A → clear suppress; retry exhaustion / Branch B → `owner_preserve`; explicit exits clear |
   | `owner_preserve` | See enter conditions below | **Yes** (durable) | **Only** new prompt, Manual Reload, session remove, **identity reset** (not mere runtime-key migration) |
   | (none) | default | No | — |

   **Enter `owner_preserve` when any of:**
   - soft-fence age-out (no typed `user_stop` envelope within 30s);
   - accepted `user_stop` without non-empty `provider_turn_id` (outcome recorded; no coordinator);
   - accepted `user_stop` with non-empty `provider_turn_id` but **no** positive
     resolved persisted conversation id yet (outcome recorded; no coordinator;
     recovery via Manual Reload/cold open after bind, or later explicit user
     action — v1 does **not** auto-start coordinator on late DB bind);
   - Branch B `RECONCILE_CANCELLED_TURN` (empty fenced detail + non-empty local);
   - coordinator retry exhaustion (missing fence / failed reads).

   - **Soft-fence age-out duration:** **30 seconds** after Stop if no typed
     `user_stop` envelope is accepted. Age-out does **not** re-enable
     automatic destructive sync; it transitions to `owner_preserve`.
   - There is **no** path that clears suppress solely by wall-clock timeout into
     “ordinary destructive sync eligible.”
   - **Rebind vs identity reset:** runtime-key rewrite that preserves the same
     logical session **migrates** soft fence / `pending_cancel` /
     `owner_preserve` / ownership. Full identity replacement, session remove,
     or backend identity reset **clears** them.
   - API name in tree may be `noteUserStopTurnOwnership` + suppress helpers;
     guards must implement one predicate:
     `cancelDestructiveSuppress = soft_fence_active OR pending_cancel OR owner_preserve`
     (not `pendingCancel` alone).
1. **Buffer promotion (unchanged role):** status-edge and/or first
   `COMPLETE_TURN` continues to snapshot `optimisticTurns + liveMessage` into
   `localTurns` with existing turn-id dedup. This path does **not** need typed
   fields to preserve content. Status-edge **must not** start unfenced detail
   reconcile and **must not** call destructive delegate/viewer terminal sync
   while `cancelDestructiveSuppress` is true for that runtime session.
2. **Outcome + coordinator (envelope-owned):** only an accepted
   `turn_complete` event with `termination_source === "user_stop"` may:
   - dispatch `RECORD_TURN_OUTCOME` (or equivalent) attaching `TurnOutcome` to
     the correct current-turn assistant (or outcome-only turn); and
   - start the cancellation reconciliation coordinator.
   Envelope acceptance compares against the **Stop-time ownership snapshot**,
   not the post-`COMPLETE_TURN` live `activeTurnToken` field (which is cleared
   by promotion). Stale envelopes after a newer prompt / generation bump no-op.

Idempotency:

- Outcome recording is idempotent by
  `(connection_id, completion_seq)` where **`completion_seq` is the
  `EventEnvelope.seq` of the accepted `turn_complete`**.
- A second delivery cannot append another footer.
- If promotion already drained live buffers, outcome attachment still works on
  the promoted assistant / synthetic outcome-only turn.
- If the typed envelope arrives **before** status-edge promotion, the
  coordinator may start after promotion of the same completion identity, or
  start immediately with a pending key that promotion must not clear.

Hook points to update (normative list):

- `acp-connections-context.tsx` — primary owner/viewer envelope acceptance for
  typed cancel fields.
- `conversation-session-surface.tsx` — keep status-edge promotion; do **not**
  start unfenced detail reconcile; do not assume envelope fields on this path.
- `conversation-detail-panel.tsx` background listener — must not double-start
  coordinator for owner tabs; may forward typed fields if it is the sole
  consumer in a given mode, but only one starter per completion key.

### CancelCompletionKey

```text
CancelCompletionKey {
  runtime_conversation_id // runtime map key (may be negative / virtual)
  connection_id
  completion_seq          // EventEnvelope.seq of accepted turn_complete
  active_turn_token       // Stop-time snapshot; may be null (viewer / already-cleared)
  provider_turn_id        // required to start coordinator
  cancel_generation       // dedicated per-session counter from Stop-time snapshot
}
```

#### Runtime vs persisted conversation ids (normative)

Codeg uses a dual-key model:

| Key | Role |
| --- | --- |
| **Runtime session key** | Map key for owner/viewer tabs; may be **negative** for draft-originated sessions. Soft fence, ownership snapshot, `pendingCancel`, and suppress gates are keyed by this id. |
| **Persisted / DB conversation id** | `session.dbConversationId ??` resolved positive id used for detail transport. Coordinator **starts** only when a resolved detail id is `> 0`. |

Rules:

1. Stop ownership and pending key **must** use the runtime key, not raw DB id.
2. Raw detail reads use the resolved positive persisted id; never call detail
   transport with a negative runtime key.
3. Runtime-key migration **migrates** ownership + soft fence + pending key +
   `owner_preserve`. Identity reset / remove **clears** them.
4. Cancel path prefers external-session → runtime id resolution when mapping
   ACP connection cancel to a tab (existing tree helpers).

**Normative generation choice:** use a **dedicated** `cancelGeneration` (or
equivalent map keyed by **runtime** id), not sole reliance on
`fetchGeneration`. Today `bumpFetchGeneration` runs on detail fetch/remove and
does **not** bump on new prompt / `APPEND_OPTIMISTIC_TURN`.

**`cancelGeneration` bump vs migrate (atomic rules):**

| Event | `cancelGeneration` | Suppress / coordinator state |
| --- | --- | --- |
| **Runtime-key migration** (same logical session; e.g. draft key → persisted key) | **Do not bump.** Move the generation counter value with the session map entry. | **Migrate** soft fence, `pending_cancel` (rewrite `runtime_conversation_id` on the key), `owner_preserve`, ownership snapshot, and coordinator timers to the new runtime id. In-flight raw reads remain valid if they still match the migrated key’s `cancel_generation` and rewritten runtime id; acceptance gates must use the **post-migration** identity. |
| **Identity replacement / rebind that replaces conversation identity** | **Bump** (invalidates Stop snapshot). | **Clear** soft fence, pending key, `owner_preserve`, timers; no auto-restart of coordinator. |
| New prompt / Manual Reload start / session remove / backend identity reset | **Bump** | **Clear** suppress states as in lifecycle table |
| Branch A success / retry exhaustion | May bump or leave per implementation; Branch A clears suppress, exhaustion enters `owner_preserve` | See lifecycle table |

Acceptance gates check the **Stop-time** `(active_turn_token, cancel_generation)`
snapshot (token may be null for pure viewers), rewritten under migration as
above, and reject envelopes whose generation no longer matches.

### Cancellation Reconciliation Coordinator

Starts only when all of these are true:

- `stop_reason == "cancelled"`;
- `termination_source == "user_stop"`;
- a **positive** resolved persisted conversation id is bound for detail transport
  (runtime key alone is insufficient if still virtual/unbound); and
- `provider_turn_id` is a non-empty string.

The coordinator captures the completion key and runtime generation, then makes
at most three non-overlapping detail reads, initially after 100 ms and then
after 300 ms and 1000 ms. These delays limit file-system churn; they are not the
correctness condition. Only the matching parsed abort outcome is the
correctness condition. After final failure, retain live content; Manual Reload /
cold open remain available. For very large rollouts, three full reparses are an
accepted cost for this delivery; no incremental/tail parse is required.

#### Raw detail read (mandatory)

The coordinator **must not** call `refetchDetail` / dispatch
`FETCH_DETAIL_SUCCESS` for apply. After `COMPLETE_TURN` the session is idle;
generic `FETCH_DETAIL_SUCCESS` without `preserveLive: true` clears
`localTurns` / `optimisticTurns` / `liveMessage` and would reintroduce the
content-drop bug.

Instead:

1. perform a **raw** detail API/transport read using the store's internal
   detail fetch helper (the same path `refetchDetail` / viewer sync use to
   obtain `DbConversationDetail`), **without** dispatching
   `FETCH_DETAIL_SUCCESS`; then
2. if the fence matches, dispatch **only** `RECONCILE_CANCELLED_TURN`;
3. otherwise discard and optionally retry.

#### Acceptance gates per response

Each response is rejected unless:

- the runtime session still exists;
- its database and external-session bindings are unchanged;
- no newer prompt has replaced `activeTurnToken` / runtime generation;
- the completion key is still the pending cancellation; and
- parsed detail contains an interrupted outcome whose `provider_turn_id`
  exactly matches the completion key (non-null match).

#### `RECONCILE_CANCELLED_TURN` merge algorithm (deterministic)

Define the **cancelled-turn local slice** as the Stop-time / pre-reconcile
projection of assistant content for this completion identity: promoted
`localTurns` + remaining `optimisticTurns` + `liveMessage` blocks that belong
to the cancelled turn (same current-turn boundary rules as outcome
attachment). A slice is **empty** iff it has no non-empty text/thinking/tool
content blocks (outcome-only metadata does not count as content).

Define the **cancelled-turn detail slice** as turns in fetched `detail` that
carry the matching interrupted outcome (`provider_turn_id` match) plus any
assistant/tool turns the parser associated with that abort attachment. The
detail slice is **empty** iff it has no non-empty content blocks (an
outcome-only assistant turn is empty content).

On fence accept, choose **exactly one** branch (no hybrid splice of partial
overlays into detail):

**Branch A — Authoritative replace** when either:
- detail cancelled-turn slice is **non-empty**, or
- both local and detail cancelled-turn slices are **empty** (intentional
  empty shell / outcome-only recovery).

Then:

1. Replace `session.detail` with the fetched detail.
2. Clear overlays detail now owns: `localTurns = []`, `optimisticTurns = []`,
   `liveMessage = null`.
3. Re-apply runtime-only state that detail cannot own (below).
4. Carry live `source = "user_stop"` onto the matched interrupted outcome;
   retain parser provider id and parser timing when present.
5. Clear pending cancel + soft fence + owner preserve, stop timers; resume
   ordinary automatic destructive sync eligibility (**Branch A only**).

**Branch B — Retain local (empty-regression skip)** when:
- fence matches, and
- detail cancelled-turn slice is **empty**, and
- local cancelled-turn slice is **non-empty**.

Then:

1. **Do not** replace `session.detail` with the empty cancelled-turn
   projection (skip detail install for this apply). Keep existing
   `session.detail` and keep local overlays for the cancelled turn.
2. Ensure interrupted outcome + `source = "user_stop"` is recorded on the
   local cancelled-turn assistant / outcome-only turn (via
   `RECORD_TURN_OUTCOME` semantics already applied or re-applied here).
3. Clear pending cancel key and coordinator timers **but enter/keep
   `owner_preserve`** so later automatic destructive sync cannot wipe the
   retained overlays with the same empty parser projection.
4. Subsequent Manual Reload / new prompt / remove / identity reset may exit
   `owner_preserve`; Manual Reload then loads authoritative detail.

**Not in v1:** partial “shorter but non-empty” detail does **not** trigger
Branch B — Branch A applies (accepted residual: live may regroup to the
parser projection). Tests must cover Branch B (fenced empty detail +
non-empty local) and Branch A (non-empty fenced detail replaces partial
local without duplication).

Preserve across Branch A:

- unresolved background settlements still relevant;
- current session statistics not covered by the response;
- bindings, cleanup flags, and ACP load errors;
- Claude-only background overlay entries beyond watermark if present (no-op
  for Codex today).

Because a newer prompt invalidates the coordinator before commit, the action
never splices an old cancelled suffix underneath a new live turn **in this
delivery**. If a new prompt already started, the coordinator is cancelled and
historical recovery is deferred to Manual Reload / cold open (see Non-Goals).

#### CancelCompletionKey lifecycle (mandatory cleanup)

Coordinator keys and timers must not leak, but **`owner_preserve` is a
separate durable suppress** that may outlive the pending key. Do **not**
interpret every terminal coordinator path as “restore automatic destructive
eligibility.”

| Event | Action |
| --- | --- |
| Successful Branch A `RECONCILE_CANCELLED_TURN` | clear key + soft fence + owner preserve + timers; auto-destructive eligible again |
| Successful Branch B `RECONCILE_CANCELLED_TURN` | clear key + timers; **enter/keep `owner_preserve`**; retain local overlays |
| Retry exhaustion (final bounded attempt failed/missing fence) | clear key + timers; retain promoted local content + footer; **enter/keep `owner_preserve`** |
| Manual Reload starts | clear key + soft fence + owner preserve + timers **before** authoritative load (Reload override); auto-destructive eligible after reload rules |
| New prompt / `activeTurnToken` replacement | clear key + soft fence + owner preserve + timers; bump `cancel_generation` |
| Runtime-key migration (same logical session) | **migrate** key + soft fence + owner preserve + ownership |
| Session remove / identity reset / backend identity reset | **clear** key + soft fence + owner preserve + timers |
| Generation loss (stale `cancel_generation`) | ignore response; clear key if generation no longer pending; do not clear `owner_preserve` solely for stale response |
| Soft-fence age-out (30s, no envelope) | `owner_preserve` (suppress stays on) |
| Accepted `user_stop` without `provider_turn_id` | record outcome; no coordinator; `owner_preserve` |
| Accepted `user_stop` with provider id but unbound detail id (`<= 0`) | record outcome; no coordinator; `owner_preserve` |

Tests must prove: (a) after Branch A success and after explicit exits
(Manual Reload / new prompt / remove / identity reset), ordinary destructive
sync is eligible; (b) after Branch B, retry exhaustion, age-out, missing
provider id, and unbound detail id, automatic destructive sync remains
**suppressed** under `owner_preserve`.

### Exclusive destructive path while `cancelDestructiveSuppress`

While `cancelDestructiveSuppress` is true for a **runtime** session
(`soft_fence_active OR pending_cancel OR owner_preserve`):

1. `syncViewerDetail` must **not** dispatch
   `FETCH_DETAIL_SUCCESS(preserveLive: false)` for that runtime session.
2. Background terminal sync / delegate terminal sync
   (`syncDelegateTerminalDetail` and status-edge callers) must not perform
   unfenced destructive replaces for that session — including pre-envelope
   soft fence, post-Branch-B `owner_preserve`, and post-exhaustion
   `owner_preserve`.
3. `refetchDetail` automatic paths used by status nudges must no-op commit or
   force non-destructive behavior until `cancelDestructiveSuppress` is false.
4. **Manual Reload** is an explicit user action: it remains authoritative and
   **may** clear suppress and load detail (user-visible risk: pre-flush partial
   detail). No special modal is required for this delivery.
5. `syncTurnMetadata` (prompting→idle metadata reparse) must neither cancel nor
   satisfy the coordinator and must not clear promoted content.

Tests must cover: Stop → idle → pre-envelope suppress; Branch B then automatic
destructive attempt still suppressed; age-out → `owner_preserve` still
suppressed; explicit exits restore eligibility.

### Bounded Failure Behavior

If a read fails, lacks the matching fence, or loses its generation race, it
must not modify displayed content. Missing-fence reads continue to the next
bounded attempt; transport and parse errors may do the same without surfacing a
blocking error banner.

After the final attempt, Codeg retains the synchronously promoted response and
its interruption footer. Manual Reload and a later cold open continue to use
the normal parser and can recover the complete persisted response. No retry
loop survives session removal, a new prompt, backend identity reset, or
successful reconciliation.

## Ordering

Events after Stop are **concurrent branches**, not a single total order.
`TurnComplete` commonly precedes a readable abort on disk; every coordinator
attempt must tolerate that reverse order.

```text
User clicks Stop
  -> FE: soft fence + Stop-time ownership snapshot (immediate)
  -> ConnectionControl::Cancel wins the active prompt
  -> bounded ready-update drain; snapshot provider id if present
  -> concurrent:
       | backend emits TurnComplete(cancelled, user_stop, provider_turn_id?)
       | Codex persists turn_aborted (may be before or after TurnComplete)
       | FE promotes live/optimistic buffers (status-edge and/or COMPLETE_TURN)
  -> accepted turn_complete envelope records typed interrupted outcome
  -> if provider_turn_id present AND positive detail id:
       start coordinator under pending key
     else if user_stop accepted but missing id/unbound detail:
       owner_preserve (no coordinator)
  -> soft fence already contributed to cancelDestructiveSuppress
  -> bounded reconciliation raw detail reads (when coordinator started)
       -> matching turn_aborted absent: retain local content, retry
       -> matching turn_aborted present: RECONCILE_CANCELLED_TURN (A or B)
  -> interruption footer remains after the recovered / retained response
```

Late envelope after soft-fence age-out (`owner_preserve`): if the envelope is
still current (generation + ownership match) and provider id + positive detail
id are present, it **may** start a fenced coordinator (`owner_preserve` →
`pending_cancel`). Branch A success may then clear suppress; Branch B returns
to `owner_preserve`. If generation is stale, no-op.

At no point does this flow enqueue, resend, resume, or continue the cancelled
prompt. Queue behavior after cancellation remains unchanged by this design;
an immediately flushed queued prompt cancels the coordinator and defers full
recovery to Reload/cold open.

## Interaction With Existing Completion Paths

- `end_turn` keeps the existing no-refetch behavior and metadata sync.
- Idle user Cancel keeps its connected-state convergence event and emits no
  `TurnComplete` or transcript reconciliation.
- Each frontend client reconciles only its own runtime session. A pure viewer
  may run the same fenced coordinator from its accepted envelope, but it cannot
  mutate another client's owner buffers and retains the existing viewer guards.
  Concurrent per-client detail reads are acceptable.
- Normal manual Reload remains an explicit authoritative detail load (may
  override pending cancel fence).
- Existing background overlay and delegation settlement rules remain in
  force; cancellation reconciliation does not invent a second ownership model.

## Risks and Mitigations

### Provider Turn Id Is Missing

Without an exact provider id, persisted replacement is unsafe. The fallback is
deliberately conservative: preserve live content and render interruption, then
allow manual Reload or cold parsing to recover later. Bounded ready-update
drain reduces avoidable misses from select bias.

### Detail Read Arrives Before File Flush

The response lacks the matching parsed `turn_aborted` outcome and is ignored.
The delay controls load only; it is never treated as evidence of completeness.

### New Prompt Starts During Reconciliation

The runtime generation and active-turn token invalidate all pending reads. An
old cancellation cannot overwrite a newer live turn. Full automatic recovery of
missing pre-stop content is deferred to Reload/cold open (explicit Non-Goal).

### Viewer Status Nudge Race

`cancelDestructiveSuppress` (`soft_fence_active OR pending_cancel OR
owner_preserve`) suppresses unfenced `preserveLive: false` commits from viewer
and background sync so a status change after user Cancel cannot win the flush
race.

### Duplicate Completion Paths

Completion outcome identity uses `(connection_id, completion_seq)`, while the
persisted fence uses `provider_turn_id`. Both must match their respective
domains, preventing duplicate footers and cross-turn reconciliation.

### Synthetic Marker Compatibility

Removing the producer prevents new markers. No global text heuristic is added,
so genuine model output is never silently deleted. A stale old live marker can
remain only until a matching fenced detail replaces that cancelled turn. AC3
allows that legacy transitional case.

### Adapter Packaging

If the registry pin / managed-prefix seed path is not updated, production
continues to emit the synthetic marker even when Codeg FE/Rust are ready. The
**LOCKED** managed-prefix + seed + pin path above is a **mandatory** delivery
prerequisite for AC3; local-only submodule verification without seed packaging
and resolver switch is incomplete.

### Fence Completeness Residual

If Codex ever appends in-scope content after `turn_aborted`, a first-match
apply can miss trailing records. **Accepted residual for v1** under the
best-effort append-order contract; fixtures document post-abort record
behavior. No mandatory double-read in this delivery.

### Live-only ACP Blocks

Some ACP-visible blocks may never appear in the rollout/parser projection.
Goal 1 guarantees stop-time visibility; Branch B retains non-empty local when
fenced detail’s cancelled-turn slice is empty; otherwise Branch A applies
parser projection.

## Acceptance Criteria

1. Stopping a Codex response like conversation 1249 leaves all currently known
   response content visible immediately.
2. Once the matching abort record is readable **before a newer prompt
   invalidates the cancellation session**, content missing from the live
   buffer is **best-effort** restored from the rollout parser projection
   without duplicate turns (append-order fence contract; not absolute
   completeness).
3. New sessions do not emit `Conversation interrupted` as an assistant summary;
   interruption appears as typed terminal status. Legacy in-memory markers may
   remain only until a matching fenced reconcile replaces that turn.
4. Automatic detail reads without the exact abort fence cannot remove, shorten,
   or reorder live content (coordinator, viewer sync, background terminal sync,
   including the pre-envelope soft-fence window after Stop).
5. Duplicate events, tab switching, viewer attachment, stale requests, and a
   subsequent prompt cannot corrupt the timeline.
6. The interrupted prompt is never automatically resumed, retried, or resent.
7. Successful `end_turn`, idle Cancel, and non-user termination behavior remain
   outside the reconciliation path.
8. Focused adapter (vendor), Rust, parser, runtime-store, and presentation
   tests pass.
9. Empty current-turn live shells never attach interruption metadata to a
   previous prompt's assistant turn.
