# User Stop Transcript Preservation and Reconciliation Design

Date: 2026-07-24

Status: Design approved in conversation; written-spec review pending

## Summary

Preserve and recover the complete response produced before a user explicitly
stops a Codex turn. A user Stop must remain a terminal action: it never resumes
or resends the prompt. The UI commits every live block it currently owns,
renders interruption as typed turn metadata rather than assistant prose, and
then performs a bounded persisted-detail reconciliation once the Codex rollout
contains the matching `turn_aborted` record.

The persisted abort record is the completion fence. Codeg must not replace a
correct live response with a detail read taken before that fence, which avoids
reintroducing the transcript-flush race documented in the existing
`completeTurn` path.

## Incident Evidence

Conversation 1249 was interrupted by an explicit user Stop after substantial
work had already been produced. Between the initiating user message and the
first abort, the original Codex rollout contains:

- 32 visible `agent_message` records;
- 222 reasoning records; and
- 139 tool calls.

Loading the same conversation through the existing cold parser restored 300
assistant sub-turns, including 32 text blocks, 129 grouped thinking blocks, and
139 tool-use/result pairs. The content was therefore not deleted from disk.

The live path instead ended with only `*Conversation interrupted*` visible:

- `CodexAcpServer.notifyConversationInterrupted` emits that string as an
  ordinary `agent_message_chunk`;
- `conversation-runtime-store.completeTurn` intentionally promotes only the
  current in-memory `liveMessage` and does not refetch persisted detail; and
- the Codex cold parser correctly preserves the rollout's `agent_message`,
  reasoning, and tool records.

The marker is not a collapsed summary and cannot reveal hidden content. It is
normal assistant prose generated by the adapter. The production evidence does
not identify the exact point at which the earlier live buffer was missed or
reset, so this design does not depend on an unproven tab-switch, reconnect, or
duplicate-status mechanism.

## Goals

1. Keep all locally observed text, thinking, tools, and results visible when a
   user stops an active Codex turn.
2. Recover earlier streamed records that are present in the rollout but absent
   from the final live buffer.
3. Represent interruption as typed terminal metadata, never as assistant text
   pretending to summarize hidden output.
4. Prevent a pre-flush persisted read from replacing richer live content.
5. Make completion and reconciliation idempotent across duplicate delivery,
   tab switching, viewer attachment, and stale detail responses.
6. Keep ordinary successful completion on its current no-refetch path.

## Non-Goals

- Automatically continuing, retrying, or resending the interrupted prompt.
- Covering terminal disconnects, process exits, application shutdown, parent
  cancellation, or other non-user interruption sources.
- Changing idle Cancel behavior. An idle Cancel continues to emit no synthetic
  `TurnComplete`.
- Diagnosing the single exact live-buffer-loss mechanism without new runtime
  instrumentation.
- Replacing the general ACP event, connection ownership, or transcript watcher
  architecture.
- Adding a database migration. Cold interruption metadata is derived from the
  rollout during parsing.
- Refetching conversation detail after every normal turn.

## Alternatives Considered

### Remove Only the Synthetic Marker

Deleting `*Conversation interrupted*` prevents a misleading final assistant
message, but it does not recover streamed blocks already missing from the live
buffer. A response could still end blank or partial.

### Immediately Replace From Persisted Detail

An unconditional `refetchDetail(..., { preserveLive: false })` after
`TurnComplete` is simple, but it repeats a known data-loss race. Existing code
documents hardware evidence where the final assistant record was only 8 ms
ahead of `TurnComplete`; a detail read in that window can omit trailing records
and overwrite the already-correct local projection.

### Selected: Typed User Stop With Abort-Fenced Reconciliation

Commit the live response synchronously, identify the user-stop completion and
the provider turn exactly, and reconcile only after the parser observes the
matching durable abort record. This repairs both full and partial live buffers
without weakening normal completion or trusting an arbitrary delay as proof of
persistence.

## Semantic Contract

### User-Stop Origin

Extend `AcpEvent::TurnComplete` with an optional, closed field:

```text
termination_source?: "user_stop"
provider_turn_id?: string
```

Only the backend branch that resolves
`TurnFinalizationDisposition::UserCancelled` sets
`termination_source = "user_stop"`. A generic `stop_reason = "cancelled"` is
not sufficient because other lifecycle paths may use the same stop reason.

Both fields are optional for wire compatibility. A cancelled event without the
typed source keeps the existing completion behavior and does not start this
design's persisted reconciliation.

### Exact Provider Correlation

When Codex reports an interrupted turn, `CodexAcpServer` already has
the provider id at `turn/started`. `CodexEventHandler` emits a metadata-only
ACP update at that boundary:

```text
session_info_update._meta.codex.activeTurnId = provider_turn_id
```

The Rust connection accepts this update only while its own turn is in flight,
stores the id as connection-local active-turn state, and clears it at terminal
finalization. The `UserCancelled` branch snapshots the stored id into
`TurnComplete.provider_turn_id` before clearing it.

This identity is delivered before cancellation rather than in the final prompt
response. Current user Stop intentionally emits `TurnComplete` immediately and
awaits the ACP prompt response only in a detached cleanup task, so relying on
response metadata would delay Stop or lose the id.

The Codex rollout's `event_msg.turn_aborted.turn_id` carries the same id. This
is the only accepted match for a persisted cancellation fence. Timestamps,
message counts, the latest turn, and literal text are not correlation keys.

If cancellation wins before Codex creates a provider turn id, Codeg still
commits the live buffers and displays interruption, but it performs no
destructive persisted replacement. There is no proven matching fence in that
case.

### Typed Turn Outcome

Add optional terminal metadata to `MessageTurn`, mirrored in Rust and
TypeScript:

```text
TurnOutcome {
  status: "interrupted"
  stop_reason: "cancelled" | "interrupted"
  source?: "user_stop"
  provider_turn_id?: string
  completed_at?: timestamp
  duration_ms?: number
}
```

The field defaults to absent during deserialization, preserving compatibility
with every existing parser and cached detail payload.

`TurnOutcome` is not a `ContentBlock::Text` and is excluded from assistant
copy, Markdown parsing, and model-visible transcript content. The timeline
renderer presents it as a compact localized footer after the affected response
group. It must not create a message bubble, accordion, or summary card.

For a response with no assistant blocks, the runtime/parser may retain an
empty assistant `MessageTurn` carrying only `outcome`; the renderer suppresses
the empty body and shows only the terminal footer. Consecutive-assistant
grouping propagates the last non-null outcome to the merged response group.

## Adapter Changes

For a Codex turn completed with status `interrupted`:

1. stop calling `notifyConversationInterrupted`;
2. do not send `*Conversation interrupted*` as an agent message chunk;
3. return `stopReason = "cancelled"` as today; and
4. map `turn/started` to the metadata-only
   `_meta.codex.activeTurnId` session-info update.

The turn-identity update produces no transcript content and remains excluded
from the backend's `is_agent_output_update` classifier. `turn/completed` and
all local terminal-finalization paths clear the stored active provider id. A
late metadata update received after `turn_in_flight` becomes false is ignored,
so an old provider id cannot leak into the next prompt.

Codeg must not add a global string filter for `Conversation interrupted`.
Model-authored text with those words remains valid content. The fix removes the
known synthetic producer, while abort-fenced reconciliation naturally removes
any stale legacy marker from the local overlay when persisted detail wins.

## Parser Changes

The Codex parser recognizes:

```json
{
  "type": "event_msg",
  "payload": {
    "type": "turn_aborted",
    "turn_id": "provider-turn-id",
    "reason": "interrupted",
    "completed_at": 1784790887,
    "duration_ms": 3377181
  }
}
```

On this record the parser:

1. flushes any pending reasoning for that provider turn;
2. preserves every previously parsed assistant/tool record;
3. attaches an interrupted `TurnOutcome` to the final assistant turn after the
   current user turn, creating an outcome-only assistant turn when necessary;
4. copies `turn_id`, `completed_at`, and duration when available; and
5. exposes the outcome in `DbConversationDetail` as part of the normal parsed
   turn list.

Seeing the matching `turn_aborted` record is a durable read fence. JSONL append
order guarantees that a reader which parsed that complete record also read the
preceding bytes in the same rollout. A truncated or malformed final line does
not produce an outcome and therefore cannot authorize replacement.

## Frontend Runtime Design

### Synchronous Completion

The existing one-stack live-to-local handoff remains the first action. At an
accepted `TurnComplete`, Codeg snapshots the current completion identity and
then promotes `optimisticTurns + liveMessage` into `localTurns` before any
persisted read:

```text
CancelCompletionKey {
  conversation_id
  connection_id
  completion_seq
  active_turn_token
  provider_turn_id
}
```

`COMPLETE_TURN` receives the typed outcome and attaches it to the last promoted
assistant turn. Its existing turn-id dedup remains in effect. Outcome recording
is independently idempotent by `(connection_id, completion_seq)`, so a second
completion delivery cannot append another footer even if live buffers are
already drained.

The current prompting-to-idle promotion fallback may remain for snapshot and
legacy delivery, but only the accepted `TurnComplete` envelope has enough data
to start cancellation reconciliation.

### Cancellation Reconciliation Coordinator

Add a cancellation-specific coordinator owned by the conversation runtime
store. It starts only when all of these are true:

- `stop_reason == "cancelled"`;
- `termination_source == "user_stop"`;
- a positive persisted conversation id is bound; and
- `provider_turn_id` is present.

The coordinator captures the completion key and runtime generation, then makes
at most three non-overlapping detail reads, initially after 100 ms and then
after 300 ms and 1000 ms. These delays limit file-system churn; they are not the
correctness condition. Only the matching parsed abort outcome is the
correctness condition.

Each response is rejected unless:

- the runtime session still exists;
- its database and external-session bindings are unchanged;
- no newer prompt has replaced `active_turn_token`/runtime generation;
- the completion key is still the pending cancellation; and
- parsed detail contains an interrupted outcome whose `provider_turn_id`
  exactly matches the completion key.

An accepted response is applied through a dedicated
`RECONCILE_CANCELLED_TURN` action, not generic
`FETCH_DETAIL_SUCCESS(preserveLive: false)`. The action installs persisted
detail through the matched abort fence, retires the now-covered local and
optimistic copies, and preserves runtime-only state that the detail cannot own:

- background overlay entries beyond the fetched watermark;
- unresolved background settlements;
- current session statistics not covered by the response; and
- bindings, cleanup flags, and ACP load errors.

The parser can prove interruption but cannot infer that Codeg's user initiated
it. On a matched reconcile, the action therefore carries the live
`source = "user_stop"` onto the persisted outcome while retaining the parser's
provider id and completion timing.

Because a newer prompt invalidates the coordinator before commit, the action
never has to splice an old cancelled suffix underneath a new live turn.

### Bounded Failure Behavior

If a read fails, lacks the matching fence, or loses its generation race, it
must not modify displayed content. Missing-fence reads continue to the next
bounded attempt; transport and parse errors may do the same without surfacing a
blocking error banner.

After the final attempt, Codeg retains the synchronously promoted response and
its interruption footer. Manual Reload and a later cold open continue to use
the normal parser and can recover the complete persisted response. No retry
loop survives session removal, a new prompt, backend identity reset, or
successful reconciliation.

## Ordering

```text
User clicks Stop
  -> ConnectionControl::Cancel wins the active prompt
  -> backend already holds provider id from Codex turn/started metadata
  -> Codex records the matching turn_aborted during interruption
  -> backend emits TurnComplete(cancelled, user_stop, provider_turn_id)
  -> frontend synchronously promotes current live/optimistic buffers
  -> frontend records typed interrupted outcome
  -> bounded reconciliation reads detail
       -> matching turn_aborted absent: retain local content, retry
       -> matching turn_aborted present: reconcile persisted detail
  -> interruption footer remains after the recovered full response
```

At no point does this flow enqueue, resend, resume, or continue the cancelled
prompt. Queue behavior after cancellation remains unchanged by this design.

## Interaction With Existing Completion Paths

- `end_turn` keeps the existing no-refetch behavior and metadata sync.
- Idle user Cancel keeps its connected-state convergence event and emits no
  `TurnComplete` or transcript reconciliation.
- Each frontend client reconciles only its own runtime session. A pure viewer
  may run the same fenced coordinator from its accepted envelope, but it cannot
  mutate another client's owner buffers and retains the existing viewer guards.
- Normal manual Reload remains an explicit authoritative detail load.
- Existing background overlay and delegation settlement rules remain in
  force; cancellation reconciliation does not invent a second ownership model.

## Presentation

The affected response keeps its normal text, thinking, tool, and result
rendering. A compact terminal footer follows it using the existing subdued
status treatment and a familiar stop/interruption icon. Localized copy conveys
only the state, for example `Response interrupted`; it does not claim that
content was summarized, hidden, retried, or completed.

The footer is not expandable because it owns no hidden transcript. Thinking
and tool controls retain their existing independent expansion behavior.

### Codex ACP Adapter

Add or update vendored TypeScript tests proving that an interrupted prompt:

1. returns `stopReason = "cancelled"`;
2. emits the exact provider turn id once through
   `_meta.codex.activeTurnId` when `turn/started` arrives;
3. emits no `Conversation interrupted` agent message chunk; and
4. still suppresses interruption output while a session is closing.

### Rust ACP Lifecycle

Add focused tests proving that:

1. `TurnFinalizationDisposition::UserCancelled` emits
   `termination_source = "user_stop"`;
2. an in-flight `_meta.codex.activeTurnId` is stored, forwarded on user Stop,
   and cleared at terminal finalization;
3. other cancelled completions do not acquire a user-stop source; and
4. metadata arriving outside an in-flight turn is ignored; and
5. idle Cancel emits no `TurnComplete` and starts no reconciliation contract.

Retain serialization compatibility coverage for events with both optional
fields absent.

### Codex Parser

Use a fixture shaped like conversation 1249 with multiple agent messages,
reasoning records, and tool pairs before `turn_aborted`. Assert that:

1. all pre-abort blocks survive parsing in order;
2. the last response carries exactly one interrupted outcome with the matching
   provider turn id;
3. a truncated abort line produces no terminal fence;
4. an abort with no assistant output produces an outcome-only response; and
5. cold parsing never synthesizes the adapter's old marker text.

### Frontend Runtime

Use fake timers and deferred detail promises to cover:

1. a complete live buffer remains visible immediately and reconciles without
   duplication;
2. a partial live buffer is replaced by the complete fenced persisted response;
3. an empty or legacy marker-only buffer recovers the complete persisted
   response;
4. a pre-fence detail response cannot clear or shorten local content;
5. a mismatched provider turn id cannot authorize replacement;
6. duplicate terminal events produce one outcome and one coordinator;
7. a tab switch or viewer attachment does not lose the pending key;
8. session removal, rebinding, or a new prompt cancels stale responses;
9. final retry failure preserves local content; and
10. ordinary `end_turn` schedules no cancellation detail read.

### Presentation

Verify that the terminal outcome renders once after the response group, is not
included in assistant-copy text, creates no empty message bubble, and remains
visible after a cold detail load. Add the new label to all supported locale
files.

## Risks and Mitigations

### Provider Turn Id Is Missing

Without an exact provider id, persisted replacement is unsafe. The fallback is
deliberately conservative: preserve live content and render interruption, then
allow manual Reload or cold parsing to recover later.

### Detail Read Arrives Before File Flush

The response lacks the matching parsed `turn_aborted` outcome and is ignored.
The delay controls load only; it is never treated as evidence of completeness.

### New Prompt Starts During Reconciliation

The runtime generation and active-turn token invalidate all pending reads. An
old cancellation cannot overwrite a newer live turn.

### Duplicate Completion Paths

Completion outcome identity uses `(connection_id, completion_seq)`, while the
persisted fence uses `provider_turn_id`. Both must match their respective
domains, preventing duplicate footers and cross-turn reconciliation.

### Synthetic Marker Compatibility

Removing the producer prevents new markers. No global text heuristic is added,
so genuine model output is never silently deleted. A stale old live marker can
remain only until a matching fenced detail replaces that cancelled turn.

## Acceptance Criteria

1. Stopping a Codex response like conversation 1249 leaves all currently known
   response content visible immediately.
2. Once the matching abort record is readable, content missing from the live
   buffer is restored from the rollout without duplicate turns.
3. `Conversation interrupted` is not emitted or rendered as an assistant
   summary; interruption appears only as typed terminal status.
4. A detail read without the exact abort fence cannot remove, shorten, or
   reorder live content.
5. Duplicate events, tab switching, viewer attachment, stale requests, and a
   subsequent prompt cannot corrupt the timeline.
6. The interrupted prompt is never automatically resumed, retried, or resent.
7. Successful `end_turn`, idle Cancel, and non-user termination behavior remain
   outside the reconciliation path.
8. Focused adapter, Rust, parser, runtime-store, and presentation tests pass.
