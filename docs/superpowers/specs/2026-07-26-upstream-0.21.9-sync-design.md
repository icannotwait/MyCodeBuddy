# Upstream 0.21.9 Sync Design

Date: 2026-07-26

Status: Approved by the user

Related:

- [Upstream synchronization policy](../../UPSTREAM_SYNC.md)
- Assessment session: `codeg://session/1937`

## Summary

Merge upstream Codeg `v0.21.9` (`e540a4fa`) into the MyCodeBuddy fork from
the current `main` lineage. Perform the integration on
`sync/codeg-0.21.9`, preserve the upstream merge ancestry, verify the resolved
tree, and then merge the verified branch into local `main`.

The dry-run assessment found a merge base of `v0.21.5` (`36bfaf2b`), 854
fork-only commits, 57 upstream-only commits, 46 conflicting files, and about
102 conflict hunks. The integration therefore uses explicit semantic review
rather than bulk selection of either side.

## Goals

1. Bring every upstream change from `v0.21.5..v0.21.9` into the fork unless it
   conflicts with an explicit MyCodeBuddy policy or reviewed replacement.
2. Preserve MyCodeBuddy branding, packaging, updater endpoints, release
   workflow, removed OpenClaw surface, and functional fork behavior.
3. Resolve overlapping ACP, connection-state, sidebar, and message-thread
   changes by composing both behaviors where they are compatible.
4. Publish the fork version as `0.21.9-mycodebuddy.1` consistently across all
   version-bearing files.
5. Leave local `main` at a tested merge commit with no unresolved conflicts or
   uncommitted integration changes.

## Non-goals

- Rebase or rewrite published MyCodeBuddy history.
- Refactor unrelated fork code while resolving conflicts.
- Push `main`, publish a release, or create a remote pull request.
- Delete unrelated branches or worktrees.

## Alternatives Considered

### A. Dedicated sync branch and merge commit (selected)

Create `sync/codeg-0.21.9` from local `main`, merge `v0.21.9` with `--no-ff`,
resolve and verify there, then merge the branch back to `main`.

This matches repository policy, isolates the conflicted state, preserves both
histories, and allows verification before changing the final `main` tip.

### B. Resolve directly on `main`

This saves one local branch but exposes `main` to a long-running conflicted
index and makes rollback or review less clear. Rejected.

### C. Cherry-pick the 57 upstream commits

This would repeat conflict resolution across commits, obscure upstream
ancestry, and risk omitting merge-dependent changes. Rejected.

## Conflict Resolution Policy

Apply these rules in order:

1. Preserve MyCodeBuddy branding, repository metadata, download links,
   updater endpoints, installer behavior, signing, compliance, and the
   Windows-only release policy.
2. Preserve the reviewed deletion of OpenClaw code unless an incoming change
   provides a deliberate replacement that is independently required.
3. Preserve fork functionality. Adapt upstream fixes around it instead of
   silently choosing `ours` for an entire conflicted file.
4. Accept upstream bug fixes and features when they do not remove fork
   behavior. For overlapping implementations, trace callers and tests on both
   sides and compose the contracts.
5. Resolve translated messages structurally: retain all fork keys, import all
   upstream keys, and keep locale schemas aligned with English.
6. Regenerate or reconcile lockfiles from the resolved manifests; do not hand
   edit dependency checksums.
7. Resolve modify/delete conflicts only after locating the fork replacement.
   Keep deletion when the old component has been superseded; otherwise port
   the incoming behavior to the replacement rather than restoring obsolete UI.
8. Merge both independently added tests in add/add conflicts and update them to
   exercise the final composed behavior.

## Integration Sequence

1. Reconfirm a clean worktree and that `v0.21.9` still resolves to
   `e540a4fa`.
2. Create `sync/codeg-0.21.9` at the approved local `main` tip.
3. Start `git merge --no-ff v0.21.9` and capture the authoritative conflict
   list.
4. Resolve version, manifest, lockfile, branding, release, and i18n conflicts.
5. Resolve UI and deleted-component conflicts against current fork call sites.
6. Resolve ACP and connection lifecycle conflicts by comparing merge-base,
   fork, and upstream implementations plus their tests.
7. Resolve message virtualization and delegation conflicts, retaining both
   test suites.
8. Audit conflict markers, unmerged index entries, upstream changed paths,
   branding files, OpenClaw deletions, and release policy before committing the
   upstream merge.
9. Run the full verification gate on the sync branch.
10. Merge the verified sync branch into local `main` and repeat the required
    verification on the final tree.

## Verification

The integration gate is:

```powershell
pnpm eslint .
pnpm test
pnpm build
pnpm test:release

Set-Location src-tauri
cargo check
cargo test --features test-utils
cargo clippy --all-targets --features test-utils -- -D warnings
cargo check --no-default-features --bin codeg-server
cargo test --no-default-features --bin codeg-server --lib
cargo clippy --no-default-features --bin codeg-server --lib -- -D warnings
cargo check --no-default-features --bin codeg-mcp
cargo clippy --no-default-features --bin codeg-mcp -- -D warnings
```

Focused tests for conflicted modules run earlier while resolving failures, but
they do not replace this full gate. Any snapshot change must be reviewed rather
than accepted blindly.

## Failure Handling

- If a test fails, identify whether the failure exists on the pre-merge fork,
  is introduced by upstream, or comes from the resolution before changing
  code.
- If dependency resolution changes more than the incoming manifests require,
  restore the intended manifest constraints and regenerate only the affected
  lockfile state.
- If a conflict exposes incompatible product contracts, stop that file's
  resolution and document the competing contracts before selecting behavior.
- Do not merge the sync branch into `main` while any required verification is
  failing.

## Success Criteria

- `git ls-files -u` and a repository-wide conflict-marker scan are empty.
- The merge commit has `v0.21.9` as an ancestor.
- All version-bearing files report `0.21.9-mycodebuddy.1`.
- Branding, updater, release workflow, and OpenClaw deletion audits match the
  fork policy.
- The full frontend, release, desktop Rust, server Rust, and `codeg-mcp`
  verification commands pass on the final local `main` tree.
- `main` is clean after the local merge and no unrelated worktree is modified.
