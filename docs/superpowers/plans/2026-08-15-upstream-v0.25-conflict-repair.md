# Upstream v0.25 Conflict Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair every confirmed semantic conflict on `merge/upstream-v0.25.0` so the branch preserves fork behavior, restores upstream v0.25 security and runtime contracts, and is ready to merge into `main`.

**Architecture:** Restore narrowly scoped upstream implementations from merge parent `3b2eece4^2`, then adapt them around the fork's current connection lifecycle, internal-session registry, history window, folder-link, and Codex environment behavior. Each subsystem gets a focused red-green test cycle and an independent commit; a final contract task verifies both transports and only then runs the repository-wide suites.

**Tech Stack:** Rust 2021, Tokio, SACP, SeaORM, Axum, Tauri 2, Next.js 16, React 19, TypeScript strict, Vitest, pnpm.

## Global Constraints

- Preserve functional fork changes according to `docs/UPSTREAM_SYNC.md`; do not replace whole current files with either merge parent.
- Preserve OpenClaw deletion, fork branding, fork release metadata, fork Codex distribution environment, and fork delegation routes.
- Use upstream merge parent `3b2eece4^2` only as the reference for missing v0.25 behavior.
- Follow strict TDD: add one focused failing test, observe the expected failure, implement the minimum behavior, and rerun the focused test.
- During Tasks 1-8, do not run `pnpm test`, `pnpm build`, repository-wide Rust tests, or all-target clippy.
- Run full frontend, release, build, desktop, server, and MCP verification only in Task 9 after every repair is implemented.
- Long Rust/build commands use a 30-60 second wait; never poll them below 10 seconds.
- Preserve existing user changes and do not rewrite unrelated code or metadata.
