Scope: R03/R04/R05/R06/R07, durable control/recovery and backup parts of R02, plus UTF-8 diagnostic truncation. Execution remains disabled by default; no paid calls were made.

## Implemented

- Acceptance reads `candidate_ref`, checks canonical bytes/hash/candidate identity and validates against the persisted host-owned result scope. Claims receive host IDs; claim/response aliases resolve to same-room durable identities; positions and evidence links are stored transactionally. Moderator results remain staged until publication. Accepted/abstained turn state is recorded before immutable projection generation.
- Close and publish validate room status/current phase, boot/run epochs, phase revision, attempt, binding incarnation, context and policy hashes in the transaction. Closing counts only the latest attempt per turn, excludes abstentions from quorum and freezes the selected attempt list. Publication verifies that list and all cleanup states, appends membership versions and only publishes this phase's evidence.
- Snapshot objects use UUID private partial files and atomic no-clobber installation. Existing content is verified, never overwritten. Rollback retains finalized content hashes because another capture may already reference them. Kept bytes remain accounted; reopened stores consult existing disk occupancy. GC returns `gc_reference_proof_required` instead of claiming unsafe deletion success.
- Projections persist all message/evidence manifests, replay state and evidence body hashes. Each event creates an immutable page manifest in the same transaction. Active budget samples and their persisted ledger sequence are included.
- Control requests, canonical request hashes, immutable initial acknowledgements, inputs and operations persist in SQLite. Stop supersedes prior controls; restart creates one successor and persists its input/budget reservation. Cleanup rejects outstanding launch intents. Recovery retires stale bindings, continues persisted operations and publishes an uncontrolled frozen closing set without issuing a model prompt. Legacy process-global test books are excluded from production builds.
- Real backups include immutable roundtable object files and validate every database-referenced blob on backup and staged restore. The in-memory reference catalog has been removed. Cloning can rehome a source manifest with a new room/version identity while retaining exact object bytes.
- Diagnostic truncation finds valid UTF-8 boundaries while retaining the byte ceiling.
- `ActiveBudgetLease` replaces production placeholder checkpoints with one durable token per room, at most one second of prepayment, monotonic settlement, current phase accounting and exact normal-finish refunds. Duplicate owners are rejected; stale owners cannot refund replacement leases. Control/crash abandonment retains the prepaid charge. Checkpoints append measurements without business events, and projections report settled usage without treating the next prepaid slice as elapsed time.
- Closing sets now retain original fences, context hashes, slot outcomes and message hashes. Recovery binds a new boot and durable recovery operation to that immutable source. Expired model deadlines cannot prevent local close/publication; outstanding cleanup still blocks publication. Restart input uses the scheduler's queued state and checks cumulative input quota, future first attempts and minimum remaining time before revocation.

## Deliberate operational limits

The object collector refuses deletion until a durable capture/backup lease proves exclusivity. Failed transactions can retain orphan content-addressed files and conservatively consume quota; this is visible retention, not evidence loss. Platform execution qualification and paid provider execution are outside this storage verification.
